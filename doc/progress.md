## Decisions
- Treat HT-077 as a canvas-first feature touching JS event wiring, resize behavior, styles, and undo semantics; do not route it as a generic UI-only polish task.
- Do not bundle tracker item T-009 into HT-077. It is adjacent to edit-mode/read-only behavior, but it is a separate race investigation and would increase scope without being part of this story's acceptance contract.
- Require an Architect RFC before implementation because this is a size-L canvas story and the current code already contains overlapping container and resize logic that needs a precise diff plan rather than exploratory edits.
- User selected the broader closeout path: remediate the current-head gate blockers rather than isolating HT-077 onto a clean closeout head.
- Current-head remediation is being treated as a bounded set of parallel fix lanes: backend contract repair, shell/design regression repair, HT-077 undo complexity cleanup, and gate-environment repair for `bandit`.
- Architect guidance for closeout: do not absorb the repo-wide `Session` ownership mismatch into HT-077. Closeout should proceed against the authoritative AGENTS mandatory gate evidence, while the broader session-contract reconciliation remains routed as HT-089.
- The user-authored canvas bug audit (`doc/bugs/canvas-bug.md`) is authoritative input for the current canvas remediation scope and will be treated as explicit acceptance criteria, not optional UX suggestions.
- The 21 Apr 2026 source and live bug-hunt results are now treated as current HT-077 blockers; PM should not route closeout validation or final review reruns until the detach payload failure and selection-target mismatch are remediated and revalidated.
- QA-Fixer is now the active tactical remediation lane for HT-077 once fail-first proofs exist; discovery has been exited for the repaired canvas defects and the remaining closeout blocker is the broader current-diff gate state, not the repaired HT-077 interaction paths themselves.
- The branch-wide gate unblock path is now explicit: fix local red tests, align the Session contract to the established request-scoped model, remove router-owned transaction outliers, then rerun CI-Gatekeeper on the full current diff before any reviewer lane restarts.
- No-behavior-change JS/file-cap refactors still require immediate stale-proof cleanup before the next authoritative gate run; test suites that slice helper text from specific fragments are part of the compatibility surface.
- API-backed published detach/reparent replay is not complete until the compensating personal-draft autosave is persisted after the base success resolver runs; forward-only persistence is insufficient because reload can resurrect stale editor-state.
