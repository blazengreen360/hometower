# HT-043: QR Code Labels for Devices

**Status:** Ready
**MoSCoW:** Could
**Kano:** Delighter — nobody expects this from a homelab tool, but Homebox and Shelf.nu feature it prominently. Print a QR label, stick it on your server, scan with your phone → jump straight to the device detail page. Bridges the physical and digital inventory.
**Phase:** 1 (Hometower)
**Size:** S (1 day)

## Job-to-be-Done
As a homelab owner, I want to generate and print a QR code label for any device so that I can stick it on the physical hardware and scan it later with my phone to instantly pull up that device's page in Hometower.

## Context
Homelab hardware lives in physical racks, closets, and shelves. When you're in front of a device and need its IP, notes, or connection info, you currently have to open Hometower, navigate to inventory, and search by name. A QR code label on the device itself eliminates that friction entirely.

The QR code encodes the device's URL: `{base_url}/devices/{device_id}`. Scanning it opens the browser directly to the device's detail page. Since a device can appear in multiple Views across different Topologies, the QR always links to the global device detail page — not a specific View.

## Acceptance Criteria

### Generation
- Given I am on a device's detail panel (HT-010), when I click the "QR Code" button (icon), then a modal/popover appears showing a QR code for this device
- Given the QR modal is open, when I scan the QR code with a phone camera, then it opens `{hometower_base_url}/devices/{device_id}` in a browser
- Given the QR code renders, when I see it, then below the code is the device name and device type in readable text (so the label is useful even without scanning)

### Print
- Given the QR modal is open, when I click "Print Label", then the browser's print dialog opens with a print-optimised layout: QR code (200×200px), device name, type, and optional IP — sized to fit a standard label sheet (62mm × 29mm or Avery 5160 equivalent)
- Given the print layout renders, when I print it, then it uses black on white (ignores the dark theme) for thermal/laser printer compatibility

### Download
- Given the QR modal is open, when I click "Download PNG", then a high-resolution PNG (400×400px) of the QR code is downloaded to my machine
- Given the PNG is downloaded, when I open it, then it has a white background, the QR code, device name, and type — suitable for pasting into a label design tool

### Batch (optional enhancement)
- Given I am on the inventory list (HT-009) and I select multiple devices (requires HT-031), when I click "Print QR Labels", then a print-optimised page generates with one label per device in a grid layout

### Security
- Given someone scans a QR code, when they are not logged in, then they are redirected to `/login` with a `next` param pointing to the device (standard auth guard behaviour)

## Non-Goals (explicitly out of scope)
- NFC / RFID tag support
- Barcode (1D) generation — QR only
- Custom label templates or sizes
- Dedicated label printer integration (Brother, DYMO APIs)
- QR code scanning within the Hometower UI itself (the phone's native camera handles this)

## Open Questions
None.

## Notes for Architect / Engineer
- **QR generation**: Use `qrcode` Python library (pure Python, no external dependencies). Generate SVG or PNG server-side via a new endpoint `GET /api/devices/{id}/qr?format=png&size=400`, or generate client-side using a JS QR library embedded via `ui.add_body_html()`.
- **Client-side approach** (recommended): Use `qrcode.js` or `qr-creator` JS library — no server round-trip needed. The QR data is just a URL string.
- **Print CSS**: Use `@media print` styles to hide everything except the label content. Or generate a print-optimised HTML page in a new window.
- **Base URL**: Read from environment variable or derive from the current `window.location.origin` on the client side. Do not hardcode.
