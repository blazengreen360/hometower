# HT-026: App Shell — Navigation Sidebar, Header Bar & Dashboard

**Status:** Ready
**MoSCoW:** Must
**Kano:** Basic — without a navigation shell the app feels like disconnected prototypes, not a product. Users cannot discover pages or orient themselves.
**Phase:** 1 (Hometower)
**Size:** L (3 days)

## Job-to-be-Done
As a homelab owner, I want a single unified interface after login — with clear navigation, a persistent header, and a dashboard overview — so that I can move between topology, inventory, and settings without memorising URLs, and I can see the health of my infrastructure at a glance.

## Context
Today, Hometower has six independent NiceGUI pages (`/topology`, `/inventory`, `/settings/locations`, `/settings/users`, `/login`, `/403`) with **zero shared navigation**. After login the user lands on `/topology` and has no visible way to reach other pages. Each page independently sets its own background colour and layout. The result feels disjoint — individual features work, but there is no sense of a unified product.

This story introduces the **structural skeleton** that wraps every authenticated page:

```
┌──────────────────────────────────────────────────┐
│  HEADER BAR  [logo] [breadcrumb]   [user menu ▾] │
├────────┬─────────────────────────────────────────┤
│        │                                         │
│  S  I  │          PAGE CONTENT                   │
│  I  D  │    (topology / inventory / dashboard    │
│  D  E  │     / settings / etc.)                  │
│  E  B  │                                         │
│  B  A  │                                         │
│  A  R  │                                         │
│  R     │                                         │
│        │                                         │
└────────┴─────────────────────────────────────────┘
```

HT-027 (Premium Design System & Theme Engine) will dress this skeleton with premium visuals, animations, and theme switching. This story focuses on **layout and navigation wiring only**, using the existing `tokens.py` palette.

### Dashboard home page (`/`)
The dashboard provides an at-a-glance summary. All data comes from existing API endpoints.

| Card | Source | Content |
|---|---|---|
| Device count | `GET /api/devices/` | Total devices, breakdown by type (top 4 types shown as mini bar) |
| Connection count | `GET /api/connections/` | Total connections |
| Location count | `GET /api/locations/` | Total locations (rack + geo) |
| Tag count | `GET /api/tags/` | Total tags |

## Acceptance Criteria

### Navigation shell
- Given I am authenticated and visit any page (`/`, `/topology`, `/inventory`, `/settings/*`), when the page loads, then I see a persistent sidebar on the left and a header bar at the top
- Given I see the sidebar, when I click a navigation item, then I navigate to that page and the active item is visually highlighted (bold + accent background)
- Given I am on `/topology`, when I look at the sidebar, then the "Topology" item is highlighted as active
- Given I am a Reader or Contributor, when I see the sidebar, then "Users" under Settings is not visible (Admin-only)
- Given I see the header bar, when I look at the top-right, then I see my email/username and a dropdown menu with: "Change Password" (placeholder until HT-025), "Logout"
- Given I click "Logout" in the user menu, when the action completes, then my session is cleared and I am redirected to `/login`
- Given I am on a page, when I look at the header bar, then I see a breadcrumb showing the current page name (e.g. "Dashboard", "Topology > Canvas", "Settings > Locations")
- Given I resize the browser to < 768px width, when the sidebar renders, then it collapses to icon-only mode with a hamburger toggle to expand

### Sidebar behaviour
- Given the sidebar is expanded, when I click the collapse button (chevron), then it smoothly animates to icon-only mode (56px wide) and my preference persists across page navigations (stored in browser localStorage)
- Given the sidebar is collapsed, when I hover over an icon, then a tooltip shows the page name

### Dashboard (`/`)
- Given I log in successfully, when the redirect completes, then I land on `/` (the dashboard), not `/topology`
- Given I am on the dashboard, when the page loads, then I see stat cards for devices, connections, locations, and tags — each showing the current count
- Given I am on the dashboard, when the page loads, then I see a "Recent Activity" section listing the 5 most recently updated devices with device name, type icon, and relative time (e.g. "2 minutes ago")
- Given I am on the dashboard, when I click the "Add Device" quick action, then I navigate to `/topology`
- Given I am on the dashboard, when I click the "View Inventory" quick action, then I navigate to `/inventory`
- Given there are zero devices, when I view the dashboard, then the stat cards show "0" and the recent activity shows an empty state message: "No devices yet — add one from Topology"

### Auth integration
- Given I am not authenticated, when I visit `/`, then I am redirected to `/login`
- Given I am authenticated, when the login page redirect fires, then it sends me to `/` (changed from `/topology`)

## Non-Goals (explicitly out of scope)
- Premium visual styling, glassmorphism, animations — that is HT-027
- Theme switching (light/dark/custom) — that is HT-027
- Real-time or WebSocket-driven dashboard updates — static load on page visit
- Notification/alert system in the header
- Map page implementation — sidebar shows a disabled "Map" link as a teaser
- Mobile-native layout (responsive sidebar is sufficient; no dedicated mobile nav)
- Search bar in the header — that is HT-020

## Notes for Architect / Engineer
- **Shared layout component**: Create `src/ui/components/app_shell.py` exporting a context manager (`with app_shell(title):`) that every authenticated page wraps its content in. This avoids duplicating sidebar/header in every page file.
- **NiceGUI patterns**: `ui.left_drawer()` for sidebar, `ui.header()` for top bar. Both are persistent across `ui.navigate.to()` if used inside a shared layout.
- **Login redirect**: Change `login.py` line 76 from `ui.navigate.to("/topology")` to `ui.navigate.to("/")`.
- **Existing pages**: Wrap `/topology`, `/inventory`, `/settings/locations`, `/settings/users` in the new `app_shell`. Remove per-page background colour setting — the shell handles it.
- **Admin-only sidebar items**: Use `get_ui_role()` from `auth_guard.py` to conditionally render "Users" link.
- **Route `/`**: Register a new `@ui.page("/")` in `src/ui/pages/dashboard.py`. Import it in `src/main.py`.
- **Sidebar collapse**: Store preference in `app.storage.user['sidebar_collapsed']`.
- **File size**: `app_shell.py` handles layout only — delegate sidebar items to a small `nav_items.py` config if the file approaches 250 lines.
