# HT-065: Canvas Visual Polish and Edge-Case Cleanup

**Status:** Ready
**MoSCoW:** Could
**Kano:** Performance — each fix incrementally improves quality; none individually causes major dissatisfaction
**Phase:** 1 (Hometower)
**Size:** M

## Job-to-be-Done

As any canvas user, I want tooltips, badges, keyboard shortcuts, and visual styles to behave correctly in edge cases — so that the polish of day-to-day interactions matches the quality of the main features.

## Context

Eleven lower-severity bugs share a common trait: each is a targeted fix in a single function or file, but together they accumulate into a noticeably rough experience.

- **BUG-TOPO-008 (Medium):** Some server data is already HTML-escaped before reaching the canvas. Applying `_htEscapeHtml()` again double-encodes it — labels show `&amp;lt;` instead of `<`.
- **BUG-TOPO-009 (Medium):** The context menu "nearest node" heuristic uses a pixel-distance threshold. At zoom < 0.5 the threshold is too tight in screen space — right-click misses nearby nodes.
- **BUG-TOPO-012 (Medium):** When draft nodes are removed programmatically (not via user cancel), `_htDraftCount` is not decremented. The draft badge shows stale or negative counts.
- **BUG-TOPO-013 (Low):** Canvas keyboard shortcuts (Ctrl+A, Delete, etc.) fire even when `document.activeElement` is a text input (e.g., device name field in the detail panel). This deletes selected nodes while the user tries to type.
- **BUG-TOPO-015 (Medium):** `applyLayoutPositions` silently skips nodes whose device UUID is not in the current device list (device was deleted). The skip is invisible — no console warning, no UI signal.
- **BUG-TOPO-016 (Low):** `window._htLastCtxX` and `window._htLastCtxY` store the last right-click coordinates globally and are never cleared. This is a minor privacy/state leak.
- **BUG-TOPO-017 (Low):** The draft form popover positions itself relative to the drag-end point. Near viewport edges (bottom, right) it clips outside the visible area.
- **IMPL-3.2 (Medium):** `_htIsDraftEdge()` may be undefined. And even when defined, it doesn't check for `draft-edge-` prefix — draft edge deletion silently fails.
- **IMPL-7.1 (Medium):** Cytoscape edge styles (selected state color) are baked at init time from `tokens.py` color values. When the user switches theme at runtime, selected edges retain the old theme's accent color until reload.
- **IMPL-2.2 (Medium):** Draft nodes are not cleared when navigating away from the topology page. If NiceGUI caches the page state, drafts persist on back-navigation — the user may think they published when they didn't.
- **IMPL-10.1 (Low):** `getCanvasJson()` calls `cy.json()` (full deep-copy of all node/edge data) on every autosave tick. On topologies with 500+ nodes this adds 50–100ms of CPU per save.

**Source bugs:** BUG-TOPO-008, BUG-TOPO-009, BUG-TOPO-012, BUG-TOPO-013, BUG-TOPO-015, BUG-TOPO-016, BUG-TOPO-017 (`bug-report-12-04-26.2.md`); IMPL-3.2, IMPL-7.1, IMPL-2.2, IMPL-10.1 (`CANVAS_IMPLEMENTATION_BUG_REPORT_20260413.md`).

## Acceptance Criteria

- Given a device name that contains `&lt;` (already server-escaped), when it renders in a canvas tooltip or context menu, then it displays as the literal text `<` — not as `&amp;lt;` (no double-encoding).
- Given the canvas is zoomed out to 0.3x, when the user right-clicks at a location near (but not exactly on) a node, then the context menu opens for that node — the nearest-node search uses graph-space coordinates scaled by `cy.zoom()`, not raw screen pixels.
- Given all draft nodes are published or cancelled, when the canvas re-renders the draft badge, then it shows `0` and never a negative number — the badge is clamped to `Math.max(0, count)` at all decrement paths.
- Given the user has a device name input field focused in the detail panel, when they press Ctrl+A, then no canvas nodes are selected — the shortcut checks `document.activeElement` is not an `<input>`, `<textarea>`, or `[contenteditable]` before acting.
- Given a saved layout references a UUID for a device that was deleted from the inventory, when `applyLayoutPositions` runs and encounters that UUID, then `console.warn('[Hometower] Layout references deleted device: {uuid} — skipping')` is emitted.
- Given an edge is selected with the dark theme accent color, when the user switches to light theme via the theme picker, then the selected edge immediately re-renders with the light theme's accent color — no page reload required.
- Given the user opens the draft form by dragging a stencil near the bottom-right viewport corner, when the form popover renders, then it shifts upward or leftward to remain fully within the viewport — it does not clip.
- Given `_htIsDraftEdge('draft-edge-abc123')` is called, when the function runs, then it returns `true`. Given `_htIsDraftEdge('published-edge-abc123')` is called, then it returns `false`. The function is always defined (no `undefined` reference error).
- Given the user navigates away from the topology page with active draft nodes, when they navigate back, then no draft nodes from the prior session are visible — the canvas initializes with a fresh state.

## Non-Goals (explicitly out of scope)

- `getCanvasJson()` incremental/dirty-flag serialization (IMPL-10.1 is Low priority; defer until load testing confirms it is a real bottleneck at production scale).
- Clearing `_htLastCtxX/Y` via a privacy-enforcing API (BUG-TOPO-016 is Low priority — clear after use is sufficient).
- Redesigning the context menu interaction model.
- Adding undo/redo support (tracked as HT-032).

## UX Interaction Spec

**Draft form popover viewport clamping:**
- After computing the popover position from the drag-end coordinates, apply: `left = Math.min(x, viewportWidth - popoverWidth - 16)` and `top = Math.min(y, viewportHeight - popoverHeight - 16)`.
- Fitts's Law: the 16px margin ensures the popover never touches the viewport edge — it remains easily tappable on mobile.

**Theme-reactive edge styles:**
- When `updateCyTheme()` is called, also call `cy.style().selector('edge:selected').cssName('line-color', newTheme.accent).update()` and the same for `target-arrow-color` — no full style rebuild required.

**Keyboard shortcut activeElement guard:**
- Check: `const active = document.activeElement; if (active && (active.tagName === 'INPUT' || active.tagName === 'TEXTAREA' || active.getAttribute('contenteditable'))) return;`
- Apply this guard to all shortcut handlers in `canvas_shortcuts.py`.

## Notes for Architect / Engineer

- BUG-TOPO-008: Audit all places that call `_htEscapeHtml()` against data origin — if data comes from the server JSON (already escaped by Python's `html.escape`), remove the client-side call. If data comes from user input directly on the canvas, keep it. Avoid blanket apply/remove.
- IMPL-3.2: Define `window._htIsDraftEdge = function(id) { return typeof id === 'string' && id.startsWith('draft-edge-'); }` alongside `_htIsDraft` in `canvas_draft.py`. Add a guard: `window._htIsDraftEdge = window._htIsDraftEdge || function(id) { ... }`.
- IMPL-2.2: Clear drafts in the NiceGUI page's teardown (page `on_disconnect` or route change event): `ui.run_javascript("if(window._cy){window._cy.nodes('.draft').remove();}")`.
- BUG-TOPO-009: Convert pixel threshold to graph units: `var threshold = 30 / cy.zoom();` before the distance comparison.
- IMPL-10.1: Defer for now — implement as a follow-up to load testing. Do not add dirty-flag machinery prematurely.
