# HT-029: Diagram Layout Management UI

**Status:** Ready
**MoSCoW:** Must
**Kano:** Basic — the data model supports multiple saved layouts but there's no way to manage them from the UI. Users are stuck with a single implicit save. Without this, the topology page is a one-diagram tool.
**Phase:** 1 (Hometower)
**Size:** S (1–2 days)

## Job-to-be-Done
As a homelab owner with a complex topology, I want to save, name, switch between, rename, and delete diagram layouts so that I can maintain multiple views of my infrastructure (e.g. "Full Topology", "Networking Only", "Docker Stack") without overwriting each other.

## Context
HT-003 built the Cytoscape.js canvas and the `DiagramLayout` model (`name` + `cytoscape_json`). The API endpoints exist (`GET/POST /api/diagrams`, `GET/DELETE /api/diagrams/{id}`). But there is **no UI** for:
- Saving the current canvas state as a named layout
- Listing saved layouts
- Loading a saved layout (switching views)
- Renaming a layout
- Deleting a layout

Today the canvas auto-saves to a single unnamed layout. This story exposes the full layout lifecycle in the topology page.

## Acceptance Criteria

### Save
- Given I am on the topology canvas as a Contributor or Admin, when I click "Save Layout" in the toolbar, then a dialog opens asking for a layout name (pre-filled with "Untitled" or the current layout name if editing an existing one)
- Given I enter a name and confirm, when the save completes, then the current Cytoscape state (node positions, zoom, pan) is persisted via `POST /api/diagrams` and I see a success toast
- Given I am viewing an existing saved layout I previously loaded, when I click "Save Layout", then the dialog pre-fills the existing name and saving updates the existing layout (via `PATCH /api/diagrams/{id}`) rather than creating a duplicate

### Load / Switch
- Given saved layouts exist, when I click the layout selector (dropdown or panel) in the topology toolbar, then I see a list of all saved layouts sorted by `updated_at` descending
- Given I select a different layout from the list, when the switch happens, then the canvas loads that layout's node positions, zoom, and pan — devices and connections come from the live database, only positions come from the layout
- Given the current canvas has unsaved changes, when I try to switch layouts, then a confirmation dialog warns: "You have unsaved changes. Switch anyway?"

### Rename
- Given I right-click (or click a menu icon on) a layout in the list, when I select "Rename", then an inline edit field appears and I can change the name
- Given I rename a layout, when the rename saves, then the list updates immediately and I see a success toast

### Delete
- Given I right-click a layout in the list, when I select "Delete", then a confirmation dialog appears: "Delete layout '{name}'? This cannot be undone."
- Given I confirm deletion, when the API call completes (`DELETE /api/diagrams/{id}`), then the layout is removed from the list and if it was the active layout, the canvas stays as-is (positions remain until the next load)

### RBAC
- Given I am a Reader, when I view the topology page, then I can see and load saved layouts but cannot save, rename, or delete

### Edge cases
- Given zero saved layouts exist, when I open the layout selector, then it shows "No saved layouts" with a prompt to save the current view
- Given I save a layout with a name that already exists (case-insensitive), when the save attempts, then I see a warning: "A layout with this name already exists. Overwrite?" with Overwrite / Cancel options

## Non-Goals (explicitly out of scope)
- Layout sharing between users or export/import of individual layouts
- Layout thumbnails or previews in the selector
- Auto-save on a timer (explicit save only)
- Layout diffing or version history
- Filtering which devices appear in a layout (all devices always appear; positions differ)

## Open Questions
None.

## Notes for Architect / Engineer
- **API gap**: `PATCH /api/diagrams/{id}` is not in the RFC route table — it needs to be added (update `name` and/or `cytoscape_json`). Min role: Contributor.
- **Toolbar location**: Add a layout selector to the topology page toolbar area (above the canvas). A dropdown button labeled with the current layout name, or "Unsaved" if no layout is loaded.
- **Unsaved state tracking**: Track whether the canvas has been modified since the last load/save. Compare current `cy.json()` with the last saved state on a debounced basis (not on every node move — too expensive). A simple "dirty" flag toggled on any canvas event is sufficient.
- **Canvas data flow**: When loading a layout, fetch devices + connections from the live DB, then apply positions from `cytoscape_json`. This means the layout is a position overlay, not a snapshot — new devices added since the last save will appear (at default positions via the layout algorithm).
