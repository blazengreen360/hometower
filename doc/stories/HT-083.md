# HT-083: Beautiful Empty States & Minimalist Onboarding

**Status:** Ready
**MoSCoW:** Should
**Kano:** Delighter -> Performance — turns a stark, broken-feeling initial experience into a helpful, guided entry.
**Phase:** 1 (Hometower)
**Size:** S

## Job-to-be-Done
As a new user logging in for the first time, I want to clearly understand what steps to take when a view has no data, so that I can quickly start building my homelab inventory.

## Context
When the database is empty, pages like Workspaces, Inventory, and Topologies simply show blank tables or empty rectangles. This lacks the "premium, polished tool" feel introduced in HT-080.
Design decision resolved in session: **Minimalist Contextual Empty States**. No gamified checklists or modal tours. Just clean, centered UI cards when a data list is empty, with a friendly illustration/icon and a primary button indicating the next logical step.

## Acceptance Criteria
- Given the Workspaces list is empty, when the user views the page, then a centered empty state card appears with a "Create First Workspace" button, rather than just an empty table.
- Given a newly created Topology, when the canvas is empty, then a subtle watermark or centered HTML overlay reads "Drag a device from the palette to begin."
- Given the canvas overlay, when the first node is placed, then the overlay automatically disappears.
- Given the Inventory table is empty, when the page renders, then it shows an empty state explaining "Devices are created when you drag them onto a topology map, or you can add one manually." with an "Add Device Manually" button.
- Given the Dashboard is viewed with zero topologies, when it renders, then an empty state prompts the user to construct their first topology.
- Given any empty state card is displayed, when rendered, then it leverages the global `--ht-text-secondary`, `--ht-bg-surface-raised`, and `--ht-accent` theme variables established in HT-080.

## Non-Goals (explicitly out of scope)
- Persistent "getting started" checklists or modal slideshow tours.
- Generating automated sample data (handled separately via the JSON import feature).

## Business Invariants
- The underlying structure of the data tables remains unchanged; the empty state is simply conditionally rendered when `len(rows) == 0`.
- The canvas empty state text must be non-interactive (e.g., `pointer-events: none`) so it doesn't block Cytoscape interactions (dragging objects onto the canvas behind the text).

## UX Interaction Spec
- **Empty State Card**: Centered horizontally and vertically in its container.
  - Large, muted Material Icon at `48px` or `64px` (e.g., `inventory_2`, `account_tree`), using `color: var(--ht-text-secondary); opacity: 0.5`.
  - H2/Title text: "No Topologies yet." Font size: `1.25rem`.
  - Body text: "Your topology map is the source of truth for your lab. Map out servers, switches, and services." Font size `0.875rem` and max-width `400px`.
  - Primary CTA Button: "Create Topology" (respects HT-080 button styling).

## Notes for Architect / Engineer
- In NiceGUI, this is a simple `if not data: render_empty_state() else: render_table()`. 
- For the Canvas, use `ui.element('div').classes('absolute-center text-center pointer-events-none')` with an ID, and a JavaScript event listener `cy.on('add')` hook that sets `display: none` the overlay as soon as `cy.nodes().length > 0`.
