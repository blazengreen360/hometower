# HT-078: Inventory Stencils Panel — Fix Empty Device List

**Status:** Ready
**MoSCoW:** Must
**Kano:** Basic — the panel exists but shows nothing, completely blocking the drag-to-place workflow
**Phase:** 1 (Hometower)
**Size:** S

## Job-to-be-Done

As a homelabber with published devices in my inventory, I want the Inventory stencils panel on the canvas to display my devices so that I can drag existing inventory items onto my topology.

## Context

The Inventory stencils panel (HT-049) was built to let users drag published devices from a sidebar onto the canvas. Currently, the panel renders its chrome (header, search box, type filter) but no device rows appear in the list. The panel is effectively non-functional.

The rendering pipeline is: Python fetches devices via `_fetch_stencil_devices()` → passes them to `render_stencils_panel()` → Python calls `ui.run_javascript("htStencilInit(...)")` → JS renders rows into `#ht-stencil-list`. The break could be at any stage: empty fetch response, incorrect JSON serialization, JS init not finding the DOM container, or the virtual scroll batch renderer failing silently.

## Acceptance Criteria

Feature: Inventory stencils panel displays devices

  Scenario: Panel shows all published devices
    Given the user has 5 published devices in the current workspace
    And the user is in edit mode on a topology page
    When the stencils panel renders
    Then all 5 devices appear as draggable rows with name, type icon, and IP
    And devices already placed on the canvas show a "Placed" badge and are greyed out

  Scenario: Panel updates when new device is created
    Given the stencils panel is open
    When the user creates a new device via the Device Tools palette
    And the device is published
    Then the stencils panel refreshes to include the new device

  Scenario: Search filters devices
    Given 10 devices are shown in the stencils panel
    When the user types "prox" in the search box
    Then only devices with "prox" in their name are shown

  Scenario: Type filter works
    Given devices of types Server, Switch, and VM exist
    When the user selects "Server" from the type filter dropdown
    Then only Server-type devices are shown

  Scenario: Empty inventory shows message
    Given the user has no published devices
    When the stencils panel renders
    Then a message "No devices in inventory" is shown instead of an empty list

  Scenario: Large inventory uses virtual scroll
    Given the user has 200 published devices
    When the stencils panel renders
    Then the first batch (50 devices) renders immediately
    And scrolling loads additional batches without full re-render

## Notes for Architect / Engineer

- **Diagnostic path:** Add `console.log` to `htStencilInit` to verify: (a) the function is called, (b) `devs` array is non-empty, (c) the DOM container `#ht-stencil-list` exists at call time. The most likely failure mode is a race condition — `ui.run_javascript` fires before NiceGUI has mounted the `#ht-stencil-list` div.
- **Race condition fix:** If `_c = document.getElementById(cid)` returns null, either defer with `requestAnimationFrame` / `setTimeout`, or use a `MutationObserver` to wait for the element.
- **Fetch validation:** Check `_fetch_stencil_devices()` in `topology_page_support.py` — verify it hits the correct API endpoint and the response schema matches what `htStencilInit` expects (array of `{id, name, type, ip, version}`).
- **NiceGUI scroll area:** The `#ht-stencil-list` div is inside a `ui.scroll_area()`. The IntersectionObserver in the JS virtual scroll uses the scroll area container as root. If the scroll area hasn't rendered or has zero height, the observer never fires and no rows appear. Ensure the scroll area has a non-zero height (e.g. `min-height: 100px`).
