# HT-048: View Designer — view mode / edit mode with RBAC gate

**Status:** Ready
**MoSCoW:** Must
**Kano:** Basic — users expect read-only and edit states to be distinct; RBAC Readers should never be able to modify a View
**Phase:** 1 (Hometower)

## Job-to-be-Done
As a homelab author, I want the View Designer to open in a safe read-only state by default so that I can browse my diagrams without risk of accidental edits, and only switch to edit mode when I intend to make changes.

## Context
In the 3-level hierarchy introduced by HT-047 (Workspace → Topology → View), a View is a named canvas perspective on a Topology (e.g. "Network", "Services", "Deployment"). The View Designer is what was previously called the Topology Designer. Two improvements needed: (1) a view/edit mode toggle so users can browse safely, and (2) RBAC enforcement — Readers can never enter edit mode. This story also gates the device type palette (HT-051), the inventory stencils panel (HT-049), and node resize (HT-050) behind edit mode since those tools have no meaning in view-only.

## Acceptance Criteria
- Given any user navigates to the View Designer, then the canvas opens in **view-only mode** by default (no toolbar, no type palette, no stencils panel, no resize handles, cursor is pan/grab only).
- Given a user has the `Reader` role, then no "Edit" button or toggle is displayed; the canvas is permanently view-only.
- Given a user has the `Contributor` or `Admin` role, then an "Edit" button (or toggle) is visible in the canvas toolbar area.
- Given a Contributor/Admin clicks "Edit", then the canvas transitions to edit mode: the editing toolbar appears, the device type palette (HT-051) and inventory stencils panel (HT-049) slide in, resize handles activate (HT-050), and drag/drop device placement is enabled.
- Given the user is in edit mode with draft devices on canvas (HT-051), when they click "Stop Editing", then a prompt warns: "You have {N} unpublished draft device(s). They will remain as drafts on this View. Continue?"
- Given the user is in edit mode with no draft devices, when they click "Stop Editing", then the canvas autosaves and returns to view-only immediately.
- Given the user navigates away while in edit mode, then a pending autosave flush is triggered before navigation (same `beforeunload` behaviour as existing autosave).
- Given the View Designer is opened via "Open" from the Views table (HT-047), then it opens in view-only mode regardless of the user's role.
- Given the View Designer is bookmarked or accessed directly via URL, then it also opens in view-only mode.

## Non-Goals (explicitly out of scope)
- No collaborative real-time editing or conflict resolution between multiple simultaneous editors.
- No per-topology "lock" mechanism (only one editor at a time) — last-write-wins remains the v1 concurrency model.
- Mode is not persisted — always opens view-only on each page load.
- No separate URL route for view vs edit (single route, mode is runtime state).

## Notes for Architect / Engineer
- Mode state is local to the NiceGUI page component — a boolean `_edit_mode: bool = False` on the page class.
- View mode: Cytoscape.js interaction options should be set to `{ userZoomingEnabled: true, userPanningEnabled: true, boxSelectionEnabled: false, autounselectify: true }` — dragging nodes and click-to-select edge creation are disabled.
- Edit mode: restore normal interaction options. The transition can be done via `cy.userInteractionOptions(...)` or by calling `cy.autoungrabify(false)` / `cy.autounselectify(false)`.
- The "Edit" button should live in the canvas toolbar bar at the top of the topology page.
- The RBAC check reuses `can_perform('write', user.role)` from `src/domain/rbac.py` (already pure domain logic).
- Depends on: HT-047. Entry point updated by HT-057: the canvas is now entered directly by clicking a Topology in the Topologies list — there is no Views table middleman. The canvas route `/topology?layout_id={id}` is unchanged.
- Unlocks: HT-049 (stencils panel only shown in edit mode), HT-050 (resize handles only active in edit mode), HT-051 (device type palette only shown in edit mode).
