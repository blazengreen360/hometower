# HT-040: Canvas Zoom & Fit Controls

**Status:** Ready
**MoSCoW:** Should
**Kano:** Performance — scroll-to-zoom works but is invisible. Visible buttons reduce the learning curve and help users who don't know trackpad gestures. Every diagramming tool (draw.io, Cloudcraft, Lucidchart) has these.
**Phase:** 1 (Hometower)
**Size:** XS (half day)

## Job-to-be-Done
As a homelab owner, I want visible Zoom In, Zoom Out, and Fit-to-Screen buttons on the topology canvas so that I can easily navigate large diagrams without needing to know keyboard/trackpad shortcuts.

## Context
Cytoscape.js supports `cy.zoom()`, `cy.fit()`, and scroll-to-zoom out of the box. HT-003 enabled scroll-to-zoom. But there are no on-screen controls — users must discover zoom via scrolling or pinch gestures. For users with a mouse (no trackpad), zooming is especially awkward.

This is a small, self-contained UI addition: a floating button group on the canvas.

## Acceptance Criteria

### Buttons
- Given I am on the topology canvas, when the canvas renders, then a vertical button group appears in the bottom-right corner with three buttons: `+` (zoom in), `−` (zoom out), `⊡` (fit to screen)
- Given the button group renders, when I inspect it, then it is positioned `16px` from the right edge and `16px` from the bottom edge of the canvas container
- Given the button group renders, when I see it, then buttons are `36×36px`, have a surface background and subtle border, and use icons (not text labels)

### Zoom in
- Given I click the `+` button, when the click fires, then the canvas zooms in by one step (1.2× multiplier) centered on the current viewport center
- Given I am at maximum zoom level, when I click `+`, then nothing happens (button does not error)

### Zoom out
- Given I click the `−` button, when the click fires, then the canvas zooms out by one step (÷1.2 multiplier) centered on the current viewport center
- Given I am at minimum zoom level, when I click `−`, then nothing happens

### Fit to screen
- Given I click the `⊡` (fit) button, when the click fires, then `cy.fit(padding=40)` is called — all nodes and edges fit within the viewport with 40px padding
- Given the canvas has zero nodes, when I click fit, then nothing happens (no error)

### Interaction
- Given the button group is visible, when I hover over a button, then it shows a tooltip: "Zoom In" / "Zoom Out" / "Fit to Screen"
- Given the buttons are in the canvas area, when I drag-pan the canvas, then the button group stays fixed (does not move with the graph)

### Theme
- Given the active theme changes (HT-027), when the button group renders, then it uses `bg-surface` and `text-primary` tokens. Before HT-027, use existing `tokens.py` values.

## Non-Goals (explicitly out of scope)
- Minimap / overview panel
- Zoom percentage indicator
- Keyboard shortcut bindings for zoom (that's HT-016)
- Reset view / center on selection

## Open Questions
None.

## Notes for Architect / Engineer
- **Implementation**: This is pure frontend — no API changes. Add a `<div>` overlay inside the canvas container with absolute positioning. JavaScript click handlers call `cy.zoom()` and `cy.fit()`.
- **Cytoscape API**: `cy.zoom({ level: cy.zoom() * 1.2, renderedPosition: { x: w/2, y: h/2 } })` for centered zoom.
- **Z-index**: Button group must be above the Cytoscape canvas but below modals/toasts.
