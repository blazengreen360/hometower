# HT-030: Connection Detail Editing UI

**Status:** Ready
**MoSCoW:** Must
**Kano:** Basic — connections without editable properties are meaningless lines. Users need to label, classify, and annotate edges to make the topology diagram useful as documentation.
**Phase:** 1 (Hometower)
**Size:** S (1–2 days)

## Job-to-be-Done
As a homelab owner, I want to click on a connection (edge) in the topology canvas and edit its properties — type, label, and notes — so that my diagram shows what kind of link each line represents (Ethernet, WiFi, Fibre, etc.) and any relevant details.

## Context
HT-004 built the Connection API (`CRUD /api/connections`) with fields: `source_id`, `target_id`, `type` (ConnectionType enum), and `label`. HT-003 renders connections as Cytoscape.js edges. But today, clicking an edge does **nothing**. There's no equivalent of the device detail panel (HT-010) for connections.

The device detail panel lives in the right column of the topology three-panel layout. This story adds an equivalent "connection detail panel" that appears when an edge is clicked (replacing the device panel contextually).

## Acceptance Criteria

### Edge click → detail panel
- Given I am on the topology canvas, when I click on an edge (connection), then the right-side detail panel switches to show the connection's properties: source device name, target device name, type, label
- Given I click on an edge, when the connection panel opens, then the previously shown device detail (if any) is replaced — only one detail panel is visible at a time
- Given I click on empty canvas space, when the click fires, then the detail panel closes (returns to empty state)

### Editing
- Given I am a Contributor or Admin and the connection panel is open, when I see the Type field, then it's a dropdown with all ConnectionType values (Ethernet, WiFi, Fibre, iSCSI, NFS, VM, Other)
- Given I change the Type dropdown value, when the change saves (auto-save on change or explicit Save button), then `PATCH /api/connections/{id}` is called and the edge style on the canvas updates to reflect the new type
- Given I edit the Label field (text input), when the change saves, then the edge label on the canvas updates in real time
- Given the save succeeds, when the UI responds, then I see a success toast (HT-036)
- Given the save fails (e.g. network error), when the UI responds, then I see an error toast and the field reverts to its previous value

### Delete
- Given the connection panel is open, when I click the "Delete Connection" button (destructive style), then a confirmation dialog appears: "Delete connection between {source} and {target}?"
- Given I confirm deletion, when the API call completes, then the edge is removed from the canvas and the panel closes

### Visual feedback
- Given I click an edge, when it becomes selected, then the edge visually highlights (thicker stroke, accent colour) to show which connection is being edited
- Given a connection has a type, when the edge renders on the canvas, then edge style varies by type: solid line for Ethernet, dashed for WiFi, dotted for VM, etc.

### RBAC
- Given I am a Reader, when I click an edge, then the connection panel opens in read-only mode — fields are displayed but not editable, no Delete button

## Non-Goals (explicitly out of scope)
- Bandwidth or speed field on connections — that's a future enhancement
- Connection port/interface mapping — that's HT-037
- Multi-select edges for bulk editing
- Connection creation from the detail panel (edges are drawn on the canvas, not created from a form)

## Open Questions
None.

## Notes for Architect / Engineer
- **Panel switching**: The right column in the topology layout currently renders `device_detail_panel`. Add a state variable (`selected_type: "device" | "connection" | None`) that determines which panel to show. Canvas click events set this state.
- **Cytoscape event**: `cy.on('tap', 'edge', handler)` fires when an edge is clicked. Extract `edge.data('id')` and fetch connection details from the API or from the already-loaded connection list.
- **Edge styles by type**: Add to `tokens.py` or the canvas JS initialization:
  - Ethernet: solid, 2px
  - WiFi: dashed (`line-style: dashed`)
  - Fibre: solid, 3px, different colour
  - VM: dotted
  - Other: solid, 1px, muted colour
- **Auto-save vs explicit save**: Recommend explicit Save button for consistency with the device detail panel pattern. Show a "dirty" indicator if unsaved changes exist.
