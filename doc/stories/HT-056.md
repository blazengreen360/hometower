# HT-056: Views table — clickable names and rename action

**Status:** Superseded
**Superseded by:** HT-057 — the Views table is being removed entirely. Topology names in the Topologies list become the direct canvas link (handled in HT-057). Rename of a topology is already on the Topologies table row. This story is no longer needed.
**MoSCoW:** Should
**Kano:** Performance — the workspace and topology name columns are links (clicking takes you deeper into the hierarchy). View names being plain text is an inconsistency that violates the established interaction pattern and forces users to hunt for the "Open" button. Rename being absent for views also breaks parity with workspace and topology rows.
**Phase:** 1 (Hometower)
**Size:** S (half day)

## Job-to-be-Done
As a homelab owner, I want to click a view's name to open it on the canvas — and rename a view if I mistype it — so that the views table is consistent with how workspace and topology names behave.

## Context
E2E sweep of HT-047 (12 Apr 2026) found two UX inconsistencies in the views table on `topology_detail.py`:

1. **View names are plain text** — unlike workspace names (links to detail page) and topology names (links to topology detail), the view name column is just `{{ props.row.name }}` with no link affordance. The only way to open a view is the "Open" button (now fixed in the E2E remediation session), but users naturally click the name expecting it to work.

2. **No rename action** — workspace and topology rows both have a pencil/edit button. The view row only has "Open" and "Delete". If a user creates a view with a typo, they must delete and recreate it.

**Rename API:** `PATCH /api/diagrams/{id}` with `{"name": "new name"}` — already exists (HT-047 backward compat). No new endpoint needed.

**Open destination:** `/topology?layout_id={view_id}` — this is the existing canvas route.

## Acceptance Criteria

### Clickable view names
- Given the topology detail page shows a views table, when I look at the "Name" column, then view names appear as links (same visual style as workspace and topology names — `var(--ht-accent)` color, no underline).
- Given I click a view name, then I navigate to `/topology?layout_id={view_id}` (same destination as the "Open" button).
- Given the "Open" button still exists after this change, clicking either the name link or the "Open" button navigates to the same destination.

### Rename action
- Given the topology detail page shows a views table, then each row has a pencil/edit icon button in the "Actions" column, alongside the existing "Open" and "Delete" buttons.
- Given I click the rename button, then a rename dialog opens pre-filled with the current view name (using the shared `show_name_dialog` component, consistent with workspace/topology rename).
- Given I submit a new valid name, then `PATCH /api/diagrams/{id}` is called with `{"name": new_name}`, the dialog closes, a "Renamed" toast appears, and the table refreshes with the new name.
- Given the API returns `409` (duplicate name within the topology), then the inline error feedback from HT-055 applies.
- Given I am a `Reader` role user, then the rename button is not visible (RBAC: Contributor+ required for writes).

### Actions column order
- Action buttons in the row follow the order: Rename (pencil) → Open (open_in_new) → Delete (trash). Rename is leftmost (most common action), Delete is rightmost with destructive colour (Norman: constraints via spatial separation).

## Non-Goals (explicitly out of scope)
- Renaming views from the canvas page itself
- Unique-name enforcement for view names within a topology (the API already handles this — `409` is the response)
- Any change to the "Open" button behaviour (already works after E2E remediation)

## UX Interaction Spec

**Name cell as link:**
```html
<q-td key="name">
  <a :href="'/topology?layout_id=' + props.row.id"
     style="color:var(--ht-accent); text-decoration:none">
    {{ props.row.name }}
  </a>
</q-td>
```

**Actions column (updated order):**
```html
<q-td key="actions">
  <q-btn flat dense icon="edit"
      @click="() => $parent.$emit('rename', props.row)" />
  <q-btn flat dense icon="open_in_new" label="Open"
      @click="() => $parent.$emit('open', props.row)" />
  <q-btn flat dense icon="delete" color="negative"
      @click="() => $parent.$emit('delete', props.row)" />
</q-td>
```

**Python handler:**
```python
table.on(
    "rename",
    lambda e: show_name_dialog(
        "Rename View", "View name",
        current_value=e.args.get("name", ""),
        on_submit=lambda n: on_rename_view(e.args["id"], n),
    ),
)
```

**Fitts:**
- Three action buttons at ~32px each with 4px gap — total ~104px in the actions column. Sufficient target size for a row action.
- Name link spans the full cell width — large target area.
