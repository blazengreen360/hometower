# HT-001: User Authentication and Session Management

**Status:** Ready
**MoSCoW:** Must
**Phase:** 1 (Hometower)
**Size:** M (3-5 days)

## Job-to-be-Done
As a homelab owner, I want to log in with my email and password so that my inventory data is protected from unauthorized access.

## Context
First-time setup creates an admin account from environment variables (`ADMIN_EMAIL`, `ADMIN_PASSWORD` in `.env`). All subsequent users are created by admins through the UI. Sessions use JWT tokens. Passwords are hashed with bcrypt.

This is the foundation for all subsequent features — nothing else can be built without auth.

## Acceptance Criteria
- Given the app starts for the first time, when I visit the login page, then an admin account is auto-created from `ADMIN_EMAIL` and `ADMIN_PASSWORD` environment variables
- Given I have valid credentials, when I submit the login form, then I receive a JWT token and am redirected to the topology canvas
- Given I have an invalid password, when I submit the login form, then I see "Invalid credentials" and remain on the login page
- Given I have a valid JWT token, when I make an API request, then the token is decoded and my user ID is attached to the request context
- Given my JWT token expires (24 hours), when I make an API request, then I receive a 401 Unauthorized and am redirected to login
- Given I click logout, when the action completes, then my JWT is cleared and I am redirected to the login page

## Non-Goals (explicitly out of scope)
- Password reset via email (not in v1)
- "Remember me" checkbox (JWT timeout is fixed at 24 hours)
- OAuth or SSO (Phase 2 / LightTower only)
- Two-factor authentication (Phase 2)
- Session concurrency limits (v1 allows multiple sessions per user)

## Open Questions
None — this is fully defined.

## Notes for Architect / Engineer
- Use `passlib` with bcrypt for password hashing (cost factor 12)
- Use `python-jose` for JWT encoding/decoding with HS256 algorithm
- Store `SECRET_KEY` in `.env` (must be 32+ random bytes)
- JWT payload: `{"sub": user_id, "exp": timestamp, "role": "Admin|Contributor|Reader"}`
- Middleware at `src/api/middleware/auth.py` decodes JWT on every protected route
- Login route is `POST /api/auth/login` with `{email, password}` → returns `{access_token, token_type}`
- Protected routes require `Authorization: Bearer <token>` header
- NiceGUI pages check auth status before rendering (redirect to `/login` if missing)
