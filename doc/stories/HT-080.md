# HT-080: UI Premiumization & Component Consistency

**Status:** Done
**MoSCoW:** Must
**Kano:** Performance — poor visual design degrades perceived quality, while a cohesive, premium UI increases trust and usability.
**Phase:** 1 (Hometower)
**Size:** L

## Job-to-be-Done

As a homelabber using Hometower daily, I want a modern, polished, and consistent user interface (typography, colors, buttons, icons) so that the app feels like a premium, reliable tool rather than a prototype.

## Context

The current UI lacks consistency across pages. Colors mismatch, typography is not systemized, button styling varies depending on the page, and the use of NiceGUI components is haphazard. 

Design decision resolved in session: **Tailwind-style admin dashboard** (clean, high-density, utility-focused). This aligns with the target demographic (infrastructure engineers and developers).

## Acceptance Criteria

- Given any page in the app, when rendered, then it strictly inherits typography from a standardized set of CSS custom properties (variables) defined in the theme engine.
- Given any primary action button (e.g. Save, Create, Add), when rendered, then its shape, padding, color, and hover states match a single global component specification.
- Given any secondary or destructive button, when rendered, then it visually indicates its priority without competing with primary buttons.
- Given the application color palette, when toggling between light, dark, and midnight themes, then the semantic colors (base, surface, primary text, secondary text, border, accent, success, error) are mapped cleanly and consistently, with no hardcoded hex values in component files.
- Given standard UI patterns (cards, dividers, lists), when instantiated via NiceGUI, then they use the native NiceGUI/Quasar components correctly rather than reinventing DOM structures manually.
- Given any section heading or label, when displayed, then its icon (if present) comes from a consolidated icon set, consistently sized and vertically aligned with the text.

## Non-Goals (explicitly out of scope)

- Rewriting canvas interaction mechanics (handled in other stories).
- Expanding the number of supported themes beyond the current 3 (Dark/Light/Midnight).
- Implementing new major features — this is strictly a UI consistency pass.

## Business Invariants

- Hardcoded colors (`#hex` or `rgb()`) are completely prohibited in UI component files (`src/ui/**/*.py`). All colors must be referenced via CSS variables (`var(--ht-*)`).
- Hometower relies on Quasar via NiceGUI. Quasar utility classes (e.g., `text-subtitle2`, `q-pa-md`) or Tailwind equivalents should be used over inline styles (`style="..."`) wherever possible.

## UX Interaction Spec

- **Typography Scale**: Define strict CSS variables: `--ht-font-h1`, heading down to `--ht-font-caption`, using a modern sans-serif (e.g., Inter/Roboto alias) and a monospace font (e.g., JetBrains/Fira Code alias) for data/IPs.
- **Button Tokens**: 
    - Primary: Filled background (`--ht-accent`), high contrast text, slight border-radius (`4px`).
    - Secondary: Outlined or flat (`transparent` bg), subtle text color, background tint on hover.
- **Form Inputs**: Dense, outlined variants for all inputs. Minimal padding, visible focus state (`ring` or `border-color` transition).

## Notes for Architect / Engineer

- Begin by auditing `src/ui/design/tokens.py` and `theme_engine.py`. Ensure all semantic tokens are fully populated.
- Run a grep sweep for inline styles containing `color:`, `background:`, or `border:` and replace them with semantic variables.
- Standardize all buttons to use `ui.button().props('unelevated')` (or `flat` / `outline`) rather than relying on default Quasar shadows, ensuring a flat, modern SaaS look.
- Use `classes()` heavily rather than `style()`.
