# HT-057: Collapse Views into Topology — direct canvas entry

**Status:** Ready
**MoSCoW:** Must
**Kano:** Basic — the extra "Views table" page between Topologies list and the canvas creates a confusing workflow for homelabbers who expect "click topology → see the diagram", not "click topology → see a table of diagrams → click Open → see the diagram"
**Phase:** 1 (Hometower)
**Size:** S (1 day)

## Job-to-be-Done
As a homelab author, I want clicking a Topology to take me straight to its canvas so that the navigation feels natural: Workspace organises my projects, Topology IS my diagram.

## Context
HT-047 introduced a 3-level hierarchy: `Workspace → Topologies list → Views table → canvas`. The intent was that one Topology could have multiple "Views" (e.g. Network, Services, Deployment). In practice this creates an unnecessary extra click and an abstract concept ("View") that maps to nothing in a homelabber's mental model. A homelabber thinks:

- "Home Projects" → workspace, organises multiple lab environments
- "Home Lab" → their homelab topology **diagram** — they expect to draw on it directly

The `DiagramLayout` (canvas JSON) can remain an implementation detail for storage, but it must not be a navigable entity in the UI. Each Topology auto-creates exactly one `DiagramLayout` on creation (already the case via HT-047's "Default View" auto-creation). HT-057 removes the Views table page (`topology_detail.py`) and wires Topology clicks directly to the canvas.

**Relationship to HT-048:** HT-048's view/edit mode toggle is unaffected — the canvas still needs that. Only the entry point changes: the canvas is accessed one click earlier (from the Topologies list, not from a Views table). HT-048's note "entered via the Views table" becomes "entered by clicking a Topology".

**Supersedes:** HT-056 (Views table — clickable names and rename) is no longer needed; the Views table itself is removed.

**Narrows HT-054 scope:** Timestamps story should drop "views table" timestamps since that table is gone.

## Acceptance Criteria

- Given a user is on the Topologies table inside a Workspace, when they click a Topology name, then they navigate directly to the Topology's canvas (the View Designer, HT-048) — no Views table in between.
- Given a user is on the Topologies table, when they click "Open" on a Topology row, then they also navigate directly to the canvas (same destination as name click).
- Given a user lands on the canvas via a Topology click, then the breadcrumb reads: `Workspaces > {workspace name} > {topology name}` (no "Views" level).
- Given the route `/workspaces/{wid}/topologies/{tid}` is navigated to directly (bookmarked, back-button), then instead of showing the Views table it redirects to the canvas for that Topology's DiagramLayout.
- Given a Topology's DiagramLayout does not yet exist (e.g. a topology created before HT-047's auto-create was in place), then one is created on first access before redirecting.
- Given the "Views" count column currently displayed in the Topologies table (workspace_detail.py), it is removed — a Topology has one canvas, so the count is always 1 and carries no information.
- Given the `topology_detail.py` page and tests for it, they are deleted.

## Non-Goals (explicitly out of scope)
- Does not introduce multiple canvases per Topology — one Topology, one canvas, always.
- Does not rename the internal `DiagramLayout` model or its DB table — it remains the storage mechanism for the canvas JSON; users never see the name.
- Does not change any canvas behaviour (HT-048 owns that).
- Does not add a "duplicate topology" / "copy canvas" feature.
- Multi-canvas per topology remains Phase 2 / LightTower if it is ever needed.

## UX Interaction Spec

**Navigation flow (revised from HT-047):**
```
Top nav "Workspaces"  →  /workspaces  (Workspace list)
  Click workspace name  →  /workspaces/{id}  (Topology table)
    Click topology name or "Open"  →  /topology?layout_id={id}  (Topology canvas — HT-048)
```

**Breadcrumb on canvas:**
```
Workspaces  >  {workspace name}  >  {topology name}
```
Each segment is a link: Workspaces → `/workspaces`, workspace name → `/workspaces/{wid}`, topology name is current page (not a link).

**Topology table columns (revised):**
- Name (link — primary action, Fitts: full row or wide cell)
- Tags
- Last Modified
- Actions: Rename (pencil icon), Delete (⋯ overflow)
- Remove: "Views" count column

**Fitts's Law note:** Topology name click is the primary action. The entire name cell should be a link, not just a small button, to maximise target size.

## Notes for Architect / Engineer
- `topology_detail.py` page is deleted. Its route `/workspaces/{wid}/topologies/{tid}` is repurposed as a server-side redirect (or the NiceGUI page function immediately fetches the topology's layout_id via `GET /api/topologies/{tid}/views/` and calls `ui.navigate.to(f"/topology?layout_id={layout_id}")` before rendering any UI).
- The simplest implementation: in `workspace_detail.py` change the "Open" button and topology name click to call `GET /api/topologies/{tid}/views/` (already exists), take `items[0].id`, and navigate to `/topology?layout_id={id}`. No new API endpoint needed.
- Auto-create guard: if `GET /api/topologies/{tid}/views/` returns an empty list, `POST /api/topologies/{tid}/views/` first with `{"name": "Default", "cytoscape_json": {"elements": {"nodes": [], "edges": []}}}`. This should be rare (only for topologies created before HT-047).
- Remove `view_count` from `TopologySummary`, `TopologyResponse`, and `workspace_detail.py` Topologies table columns.
- Remove `src/ui/pages/topology_detail.py` and its import from `src/main.py`.
- Delete or update tests that reference `topology_detail_page` or the views table route.
- Update `HT-048` canvas page breadcrumb to reflect 2-level breadcrumb (workspace + topology, no view level).
