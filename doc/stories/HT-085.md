# HT-085: Financial Power Management (Cost Tracking)

**Status:** Ready
**MoSCoW:** Should
**Kano:** Performance — adding real financial tracking turns a static watt counter into an active homelab budgeting tool.
**Phase:** 1 (Hometower)
**Size:** M

## Job-to-be-Done

As a homelabber or IT admin, I want to assign an electricity cost rate (`$/kWh`) to my locations so that I can see the estimated monthly and yearly operational cost (OPEX) of running my equipment, both per-device and in aggregate.

## Context

HT-044 introduced basic power tracking (inputting Watts per device). HT-082 added a dashboard widget summing those Watts. However, knowing a lab draws "840W" is abstract. Translating that to "$90.72/month" is actionable, allowing users to make decisions about decommissioning old hardware or moving services.

Design decision resolved in session: **Financial / Cost Tracking** with a **Per-Location Rate** (to properly handle a local home lab vs a remote datacenter/colo). UPS mapping was explicitly excluded.

## Acceptance Criteria

Feature: Electricity Cost Calculation

  Scenario: Setting electricity rates per Location
    Given the user navigates to `/settings/locations`
    When creating or editing a Location
    Then there is a numeric input for "Electricity Rate ($/kWh)", defaulting to 0.00
    And there is an optional string input for "Currency Symbol" (e.g., `$`, `€`, `£`), defaulting to `$`
    And saving the form persists these values to the Location record in the database

  Scenario: Viewing estimated cost on Device Detail
    Given a device belongs to a Location with a populated electricity rate ($0.15/kWh)
    And the device has an active power draw of 100W
    When the user views the device Properties panel (Power section)
    Then the panel displays the math: "100W @ $0.15/kWh = $10.80 / month ($131.40 / year)"
    And the calculation accurately multiplies watts * 24h * 30 days (720h/mo) or 365 days (8760h/yr)

  Scenario: Devices with no location rate
    Given a device has a power draw but belongs to no location, or its location has no rate set
    When the user views its Power section
    Then it simply displays the raw Wattage
    And a helpful hint says, "Set an electricity rate on the Location to see estimated costs."

  Scenario: Dashboard Power Widget roll-up
    Given the user views the Power Widget on the Dashboard (HT-082)
    When the widget aggregates power load across devices
    Then it also aggregates and displays the total estimated monthly OPEX (e.g., "Total Draw: 1,200W | Est. Cost: $125.00/mo")
    And it correctly sums costs using the varying rates of different locations (e.g., Device A at Home vs. Device B at Colo)

  Scenario: Status-aware power draw (Idle/Active)
    Given a device has a status of "Offline" or "Decommissioned"
    When the system aggregates power and cost
    Then its wattage and cost are treated as 0
    And when the status is "Active", "Maintenance", or "Planned", it uses its configured wattage

## Non-Goals (explicitly out of scope)

- Dynamic Idle vs. Peak load tracking (static Wattage * 24/7 is assumed for standard homelab baseline).
- UPS load percentage / battery runtime modeling.
- Complex Tiered or Time-of-Use (TOU) billing rates. A flat scalar `$/kWh` per location is sufficient.

## Business Invariants

- The calculation formula must be strictly standardized across the app: `(Watts / 1000) * Rate * 720` for monthly, and `(Watts / 1000) * Rate * 8760` for yearly.
- Historical cost tracking is not required. Modifying a location's rate updates the "current run rate" projection dynamically.

## UX Interaction Spec

- **Location Settings Modal**: Add an "Electricity Rate (kWh)" input field below the Name/Description fields. Prefix the input with a dropdown for Currency Symbol.
- **Device Detail Panel**: In the "Power" collapsible section, display the Wattage input. Below it, show a read-only calculated projection box (e.g., a small grey callout box: `Estimated Cost: **$X.XX** / mo`).
- **Dashboard Widget**: Break the Power card into two primary metrics: Total Watts (large) and Total Monthly Cost (large). 

## Notes for Architect / Engineer

- **Database Change**: This requires an Alembic migration to add `electricity_rate: float | None` and `currency_symbol: str` (default `$`) to the `Location` table.
- **Service Layer**: Add a `calculate_device_monthly_cost(device: Device, location_rate: float) -> float` utility to centralize the math logic to prevent drift between the UI device panel and the dashboard aggregator.
- **Dashboard Query**: For the dashboard cost rollup, either join the device and location tables to multiply `(sum(device.watts) / 1000) * location.electricity_rate * 720` in SQL, or fetch and fold in Python if the total row count is reasonable. Ensure "Offline" devices do not contribute to the total.
