## Job-to-be-Done

As a Contributor, I want the canvas edit mode toggle, node interactions, and tooltips to respond predictably every time I use them, so that I don't get stuck in a broken UI state requiring a page reload.

## Context

Five bugs converge on canvas event binding and interaction dispatch:

- **BUG-TOPO-019 (High, dynamically verified):** Rapidly toggling "Edit / Stop Editing" while a draft-confirmation dialog is open stacks a second backdrop behind the first. All subsequent toggle clicks are intercepted by the orphaned backdrop and the button stops responding. The only recovery is a page reload. Playwright stress tests confirmed this 19/40 times (deterministic).
- **BUG-TOPO-010 (Medium):** `_htEventsWired` guard correctly prevents double-binding on the same page load, but if NiceGUI reuses page state across route changes without a full component teardown, the guard's value may be stale — giving a second full event registration on re-entry.
- **BUG-TOPO-020 (Medium):** The tooltip component fires `GET /api/devices/{nodeId}?include=services` for every hovered node. Draft nodes have IDs like `draft-abc123` which the API correctly rejects with 422, but the client never guards against it — producing 4+ 422s per session (confirmed in stress runs).
- **IMPL-4.1 (High):** The node `tap` event is registered twice: once in `canvas_js.py` (view-mode path) and once in `_htInitEventHandlers` (edit-mode path). In edit mode both fire, potentially opening the detail panel in response to a drag-start click.
- **IMPL-4.2 (Medium):** The `contextmenu` / `cxttap` deduplication uses a 200ms time window. On slow hardware the cxttap handler may complete >200ms after the native event, causing both to fire and the context menu to open twice.

**Source bugs:** BUG-TOPO-010, BUG-TOPO-019, BUG-TOPO-020 (`bug-report-12-04-26.2.md`); IMPL-4.1, IMPL-4.2 (`CANVAS_IMPLEMENTATION_BUG_REPORT_20260413.md`).

## Acceptance Criteria

- Given a draft-confirmation dialog is open on the canvas, when the user clicks "Edit / Stop Editing" toggle, then the click is ignored (not queued, not stacked) — no second backdrop is added, and the toggle resumes normal operation once the dialog is dismissed.
- Given the user stress-toggles edit mode 40 times with dialogs open and closed, when any run completes, then zero orphaned backdrop elements exist in the DOM (`document.querySelectorAll('.q-dialog__backdrop').length <= 1`).
- Given the user navigates away from the topology page and back, when edit mode is toggled after return, then canvas events are bound exactly once — `_htEventsWired` is reset to `false` on page teardown so the guard works correctly on re-entry.
- Given a draft node (ID starting with `draft-`) is hovered, when the tooltip renders, then no HTTP request is made to `/api/devices/draft-*` — the tooltip shows a static label: *"Unpublished draft — publish to save"*.
- Given the user single-clicks a node in edit mode (not dragging), when the tap handler fires, then the detail panel opens exactly once — not twice from two registered handlers.
- Given the user right-clicks a node on desktop (both `cxttap` and native `contextmenu` fire), when both events arrive within 50ms, then the context menu opens exactly once.

## Non-Goals (explicitly out of scope)

- Redesigning the edit mode toggle button (HT-048 owns that UX).
- Adding new context menu items (tracked separately).
- Removing the draft confirmation dialog flow (it is a feature, not a bug).

## UX Interaction Spec

**Toggle deadlock prevention:**
- The toggle button sets a flag `_htToggleLocked = true` while a dialog is in progress.
- While locked, the button is visually disabled (50% opacity, `cursor: not-allowed`) so the user has feedback that the action is unavailable — not just silently ignored.
- Norman's Feedback: the disabled state lasts until the dialog's Promise resolves or rejects.

**Draft node tooltip:**
- Static content: device icon + *"Unpublished draft — publish to save"* in italics.
- No loading spinner (no API call to wait on).

## Notes for Architect / Engineer

- BUG-TOPO-019 fix: `topology_edit_toggle.py:42` — gate `dlg.open()` behind a guard flag that is set on open and cleared in the dialog's `on_value_change` callback. Alternatively, check `dlg.value` before calling `dlg.open()`.
- `_htEventsWired` reset: add teardown in the NiceGUI page's `on_disconnect` or equivalent page lifecycle hook — set `window._htEventsWired = false` via `ui.run_javascript()`.
- Tooltip draft guard: `canvas_tooltip.py:19` — before firing the `fetch`, check `if (nodeId.startsWith('draft-')) { return; }`.
- IMPL-4.1 fix: merge the two `tap` node handlers into one, branching on `window.HT_READONLY` internally. The outer canvas_js.py guard `if (!window.HT_READONLY) return;` already makes it safe — but having two handlers means one always fires even when the other returns early.
- IMPL-4.2 fix: replace the 200ms time check with a boolean flag `window._htCtxMenuHandled` reset via `setTimeout(..., 0)` after the cxttap handler fires.
