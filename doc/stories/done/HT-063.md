# HT-063: Canvas Initialization Robustness and Layout Restoration

**Status:** Done
**MoSCoW:** Should
**Kano:** Basic (IMPL-1.2 — stacked nodes is a blank first experience) / Performance (others — degrade layout fidelity)
**Phase:** 1 (Hometower)
**Size:** M

## Job-to-be-Done

As any user, I want the topology canvas to initialize correctly the first time on any device — with nodes visible, my saved zoom/pan intact, and no ghost draft nodes from previous sessions — so that I never have to reload just to see my diagram.

## Context

Six related bugs all affect the sequence of events from page load to a rendered, correct canvas:

- **IMPL-1.1 (High):** The init retry loop waits for `container.clientWidth > 0` but not for CSS Grid/Flexbox layout to stabilize. On slow devices, Cytoscape can initialize at the wrong container size (CSS not yet applied) — nodes clip or misalign until reload.
- **IMPL-1.2 (High):** The auto-layout for unpositioned nodes (nodes at 0,0) only runs when a saved layout exists. New topologies with no saved layout skip the check entirely — all nodes stack at origin (0,0) and appear as a single blob.
- **IMPL-5.1 (Medium):** After restoring saved pan/zoom, if any unpositioned nodes exist, `cy.fit()` is called — overwriting the just-restored zoom/pan values. Users who carefully set zoom lose it every time they add a new device.
- **IMPL-5.2 (Medium):** The collapsed container state restoration (`_collapsed` data flag) runs after `cy.layout().run()`. If the layout throws, the collapsed pass is never reached — containers appear expanded on reload.
- **IMPL-9.1 (Medium):** Nodes at canvas position exactly (0,0) are misidentified as "unpositioned" and moved to the overflow column. A user who intentionally anchors a root node at the origin loses its position on every reload.
- **CANVAS-NODES-LEFTOVER (E2E routed to Architect):** Orphaned `draft-{UUID}` nodes from prior API test runs (or browser sessions) persist in the autosaved layout JSON across page loads. They render as broken nodes with no corresponding inventory device.

**Source bugs:** IMPL-1.1, IMPL-1.2, IMPL-5.1, IMPL-5.2, IMPL-9.1 (`CANVAS_IMPLEMENTATION_BUG_REPORT_20260413.md`); CANVAS-NODES-LEFTOVER (`bug-report-e2e-01.md`, routed to Architect).

## Acceptance Criteria

- Given the page loads on a throttled device (CPU 4x slowdown), when the canvas container has non-zero dimensions but the parent CSS Grid layout is still settling, then canvas initialization is deferred until `requestAnimationFrame` confirms the container dimensions are stable for two consecutive frames — no clipping or wrong-size init.
- Given a new topology with 5 devices and no saved layout yet, when the canvas loads for the first time, then nodes are automatically distributed via COSE layout — none are stacked at (0,0).
- Given a saved layout with `pan={x:100, y:50}` and `zoom=2.0` and one new device added since the last save, when the page loads, then: (a) the new device is placed in a reasonable position (not at 0,0), (b) the saved pan and zoom are preserved for all other nodes — `cy.fit()` is not called when a valid saved zoom exists.
- Given a container node was saved in collapsed state (`_collapsed: true`), when Cytoscape layout init throws an error and falls back to default, then the collapsed styling is applied in a separate `try/catch` recovery pass after the error — the container renders collapsed, not expanded.
- Given a device was intentionally saved at canvas position exactly (0,0), when the layout loads, then that device remains at (0,0) — it is not relocated to the "new node" overflow position. (The unpositioned detection must use an explicit `_positioned` data attribute rather than coordinate equality.)
- Given the autosaved layout JSON contains node IDs prefixed with `draft-`, when the canvas loads, then those nodes are pruned from the layout before Cytoscape initializes — no draft ghost nodes appear — and the cleaned layout is written back to the autosave.

## Non-Goals (explicitly out of scope)

- Animated layout transitions on page load.
- Persisting collapsed/expanded state to the server (it is stored in the in-memory `cytoscape_json` of the DiagramLayout, which is already saved via autosave).
- Multi-viewport synchronized pan/zoom.

## UX Interaction Spec

**First-load (no saved layout):**
- COSE layout runs automatically, fits all nodes with 40px padding.
- No user action required; nodes are always visible on first open.

**New device on existing layout:**
- New node placed at `{x: existingBoundingBox.x2 + 100, y: (existingBoundingBox.y1 + existingBoundingBox.y2) / 2}` — to the right of the existing diagram, vertically centered.
- Existing zoom/pan is not disturbed.

**Draft ghost pruning:**
- Silent — no toast. Pruned nodes are simply not rendered. If the count of pruned nodes > 0, a `console.info('[Hometower] Pruned {N} orphaned draft nodes from saved layout.')` is emitted for debugging.

## Notes for Architect / Engineer

- IMPL-1.1 fix: after checking `clientWidth > 0`, add a `requestAnimationFrame` round-trip before proceeding: `requestAnimationFrame(function() { if (container.clientWidth > 0 && container.clientHeight > 0) { initCanvas(...) } else { retry } })`.
- IMPL-1.2 fix: move the unpositioned-node check *outside* the `if (savedPositions && savedPositions.pan)` conditional — run it always.
- IMPL-5.1 fix: only call `cy.fit()` when unpositioned nodes > 0 AND `!savedPositions.pan` — i.e., don't fit when there's a saved pan. When fitting, accept that saved zoom is overridden (user added new devices — they expect to see them). When not fitting, apply saved zoom/pan.
- IMPL-9.1 fix: add a `_positioned: true` flag to every node when its position is first explicitly set (via drag or save). The unpositioned check uses `n.data('_positioned') !== true` rather than `p.x === 0 && p.y === 0`. This must be set for all existing nodes when the layout is first saved (retrofit via save migration).
- CANVAS-NODES-LEFTOVER: prune in `initCanvas()` before passing elements to `cytoscape({...})` — filter `elements` array to remove any item where `data.id.startsWith('draft-')`. Then persist cleaned layout immediately.
