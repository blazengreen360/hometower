# HT-061: Fix Inventory Delete Action and Mobile Drawer Accessibility

**Status:** Done
**MoSCoW:** Must
**Kano:** Basic — a broken delete button on a core feature causes dissatisfaction; mobile inaccessibility excludes a user segment
**Phase:** 1 (Hometower)
**Size:** S
**Shipped:** 13 April 2026

## Job-to-be-Done

As a Contributor on any device, I want to delete devices from the inventory table and interact with all row actions, so that I can manage my inventory without switching to a different view.

## Context

Two High-severity bugs uncovered by Playwright inventory stress testing completely block workflows:

- **BUG-INV-001 (High):** The delete icon in inventory table rows emits `delete-device` via `$parent.$emit(...)` from a Quasar table slot template. Under the current NiceGUI slot context this event does not reach the listener on `inventory_page` — zero placement lookups are fired, zero delete dialogs open, zero API calls are made. The delete action is completely non-functional.
- **BUG-INV-002 (High):** On viewports ≤ 768px, `.q-drawer__backdrop` is present and visible immediately after page load (before the user has opened the drawer). It intercepts all pointer events, making row actions un-tappable and causing accidental navigation.

**Source bugs:** BUG-INV-001, BUG-INV-002 (`bug-report-12-04-26.3.md`).

## Acceptance Criteria

- Given any device row in `/inventory`, when a Contributor or Admin clicks the delete icon, then a confirmation dialog opens within 500ms — listing the device name and the number of topology placements where it appears.
- Given the confirmation dialog is open, when the user clicks **Confirm delete**, then `DELETE /api/devices/{id}` fires, the row disappears from the table, and a success toast appears.
- Given the confirmation dialog is open, when the user clicks **Cancel**, then no API call is made and the table is unchanged.
- Given the user's viewport is ≤ 768px wide, when `/inventory` loads, then `.q-drawer__backdrop` is **not present** in the DOM — the drawer starts closed on mobile without an overlay.
- Given a mobile user explicitly opens the navigation drawer, when they tap the backdrop to close it, then the backdrop is removed and all inventory row actions are tappable immediately after.

## Non-Goals (explicitly out of scope)

- Bulk delete from the inventory table (tracked as HT-031).
- Desktop responsive layout changes.
- Redesigning the confirmation dialog beyond the current pattern.

## UX Interaction Spec

**Delete confirmation dialog:**
- Title: *"Delete {device name}?"*
- Body: If `placements > 0`: *"This device appears in {N} topology diagram(s). Removing it will leave orphaned canvas nodes."* If `placements === 0`: *"This device has no topology placements."*
- Buttons: `Cancel` (default focus) | `Delete device` (destructive, right-aligned).
- Norman's Feedback: spinner on the Delete button while the API call is in flight; replaced with checkmark on success.

**Mobile drawer:**
- `show-if-above` or equivalent Quasar prop/breakpoint guard prevents overlay mode activating on load.
- Persisted desktop expansion state must not propagate to mobile initial state.

## Notes for Architect / Engineer

- BUG-INV-001 root: Replace `$parent.$emit()` event chain in the Quasar table slot with a direct Python-callable row action pattern already used elsewhere in NiceGUI (e.g., `ui.button(on_click=lambda: ...)` bound per row, or a known-working table row click mechanism). Avoid slot-level `$emit` chains in NiceGUI — they are unreliable.
- BUG-INV-002 root: `src/ui/components/sidebar.py:39` — add a mobile breakpoint guard when setting the initial drawer `value` from persisted preferences. NiceGUI's `ui.left_drawer` accepts `show-if-above` via `.props()`.
- The placements lookup (`GET /api/devices/{id}/placements`) must fire before the dialog opens — not after the user confirms. This is already the intended design per the original story; BUG-INV-001 prevented it from ever running.
