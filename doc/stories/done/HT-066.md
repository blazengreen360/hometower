# HT-066: Convert Sync Database Routers off the ASGI Event Loop

**Status:** Done
**MoSCoW:** Must
**Kano:** Basic — global request starvation is a release blocker regardless of UX quality elsewhere
**Phase:** 1 (Hometower)
**Size:** M
**Shipped:** 13 April 2026

## Job-to-be-Done

As any authenticated user, I want one slow database-backed API request to not freeze every other request in the app, so that the whole system stays responsive under normal concurrent use.

## Context

**BUG-1102-01 (Critical)** identifies a systemic FastAPI misuse: router handlers across `src/api/routers/*.py` are declared as `async def` while calling synchronous SQLModel `Session` operations. In FastAPI this runs the handler body on the main event loop thread; sync DB calls then block the loop and starve unrelated traffic.

This is not isolated to one route. The report explicitly calls out `devices.py`, `topologies.py`, `workspaces.py`, `locations.py`, and indicates the pattern is widespread across the router layer.

**Source bug:** BUG-1102-01 (`doc/bugs/bug-report-11-04-26.2.md`).

## Acceptance Criteria

- Given a route handler performs synchronous SQLModel/Session work, when the handler is defined in `src/api/routers/`, then it is declared as standard `def`, not `async def`, unless it performs real awaited async I/O.
- Given two concurrent requests are sent, one to a slow DB-backed endpoint and one to a cheap endpoint, when the slow endpoint is executing, then the cheap endpoint still completes without waiting for the slow query to release the main event loop.
- Given the router sweep is complete, when the architecture grep is run against `src/api/routers/`, then no DB-backed path operation remains `async def` unless explicitly documented as async-only and using awaited async APIs.
- Given the refactor changes signatures across many routers, when the full verification gate runs, then pytest, mypy, docker build, and architecture grep checks all pass.

## Non-Goals (explicitly out of scope)

- Migrating the backend to SQLAlchemy async engine / AsyncSession.
- Rewriting services or repositories to async APIs.
- Performance tuning individual SQL queries.

## Notes for Architect / Engineer

- This is a systemic sweep across the router layer, not a single-file bug fix.
- Preserve route contracts, dependencies, and response models exactly; only the execution model changes.
- Feature-Engineer reminder from PM memory: keep file-size cap in mind and avoid inline extractions that leave files >250 lines.
- Code-Reviewer should specifically audit that no `async def` remains for sync Session handlers after the sweep.
