# HT-049: Inventory stencils panel — drag published devices onto a View

**Status:** Ready
**MoSCoW:** Should
**Kano:** Delighter — unexpected: homelabbers don't expect Netbox-style inventory re-use in a canvas tool; this differentiates Hometower from both Netbox and manual wikis
**Phase:** 1 (Hometower)

## Job-to-be-Done
As a homelab author, I want to drag an already-published inventory device onto a different View so that I can reuse the same physical device across multiple perspectives (e.g. a server that appears in both the Network View and the Services View) without duplicating its inventory record.

## Context
New devices are created diagram-first via the device type palette (HT-051): drag a type icon → fill form → canvas draft → Publish to inventory. This story covers the complementary flow: placing an **already-published** device (one that exists in global inventory) onto a View. It is the inventory re-use path, not the creation path. The panel is only visible in edit mode (HT-048) and sits on the left sidebar alongside the device type palette.

**Scoping note:** With diagram-first creation (HT-051), the canvas is opt-in by design — only explicitly placed devices appear on a View. The `cytoscape_json` element list is the source of truth for what is placed. This story reinforces that model: dragging from the stencil panel adds an element entry; deleting from canvas removes it.

## Acceptance Criteria
- Given the Topology Designer is in edit mode, then a collapsible "Inventory" panel is visible on the left side of the canvas.
- Given the panel is open, it shows all devices from the inventory as rows: device icon (by type), name, type badge, and IP (if set).
- Given the user types in the search box, then the list filters in real-time by device name (case-insensitive substring match).
- Given the user opens a type filter dropdown, then they can filter the stencil list to a single `DeviceType`.
- Given the user drags a device from the stencil panel and drops it onto the canvas, then a node for that device appears at the drop position on the current topology.
- Given the user drops the same device onto the canvas a second time, then a second node for that device is NOT added (one device = one node per topology; the panel greys out already-placed devices with a "placed" indicator).
- Given a placed device is later removed from the canvas (Delete key), then the stencil panel shows it as available (unplaced) again.
- Given the panel is collapsed, then the canvas occupies the full viewport width; expanding the panel slides the canvas content area.
- Given the topology has more than 100 devices in inventory, then the stencil list is virtualised (only visible rows rendered) so the panel remains responsive.

## Non-Goals (explicitly out of scope)
- Does not create new devices — new device creation is handled by the device type palette (HT-051). The stencil panel is re-use only.
- Does not show connections in the stencil panel (only devices).
- Does not allow reordering or grouping within the stencil panel.
- Stencil panel is not available in view-only mode.
- Does not filter by location/rack in this story.

## Notes for Architect / Engineer
**Key architectural decision (Architect must resolve before implementation):**
Current behaviour: `topology_data.py` loads ALL devices from `GET /api/devices/` onto every canvas. An opt-in model requires tracking which devices are placed on which layout. Two options:
1. **cytoscape_json as source of truth** — only devices whose IDs appear in the layout's `cytoscape_json` elements are loaded; placement = adding an element entry; removal = removing it. Simpler, no new join table.
2. **`layout_devices` join table** — explicit `(layout_id, device_id)` rows; cytoscape_json stores positions only. More normalised but a new migration and more complex.
The product prefers option 1 (cytoscape_json as source of truth) for simplicity, but Architect may override.

**UI:**
- Panel component: `src/ui/components/stencils_panel.py` (new)
- Drag source: HTML5 drag API or Cytoscape.js `cy.add()` on drop — needs Architect evaluation for the drag-to-canvas handoff
- Panel width: 260px collapsed to 0 (icon toggle strip) via CSS transition
- Depends on: HT-048 (only shown in edit mode)
