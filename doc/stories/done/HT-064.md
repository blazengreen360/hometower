# HT-064: Security Hardening — Endpoint Exposure, Rate Limits, Error Sanitization, XSS

**Status:** Done
**MoSCoW:** Must
**Kano:** Basic — security vulnerabilities are must-fix regardless of user satisfaction with features
**Phase:** 1 (Hometower)
**Size:** S
**Shipped:** 13 April 2026

## Job-to-be-Done

As a self-hosted homelab operator, I want my Hometower instance to not leak internal system information to unauthenticated scanners, limit blast radius of abusive API calls, and not execute injected scripts from device labels — so that my homelab management tool itself is not an attack surface.

## Context

Five security findings from the Security-Orchestrator audit (`findings-report-11-04-26.2.md`) plus one XSS bug from the canvas bug report require remediation before GA:

- **SEC-1104-01 (High):** Raw PostgreSQL `exc.orig` exception string is returned in HTTP 422 responses from the import endpoint — leaks table names, column names, and constraint names to any Admin who sends crafted payloads.
- **SEC-1104-02 (High):** `GET /api/health` is excluded from auth and returns the exact `version` string — unauthenticated network scanners can identify the Hometower version and look up CVEs.
- **SEC-1104-03 (Medium):** `GET /api/system/stats` returns `db_version` (full PostgreSQL version string including OS arch, compiler) to all Reader-role users — only Admins need DB diagnostics.
- **SEC-1104-04 (Medium):** Rate limiting is applied only to `POST /api/auth/login`. `GET /api/export` (full DB dump), `POST /api/import?confirm=true` (TRUNCATE+INSERT), and `DELETE /api/devices/{id}` are unthrottled — DoS vector for any Contributor.
- **BUG-TOPO-014 (High):** The edge-delete confirm dialog renders the raw `label` field from Cytoscape edge data without HTML-escaping — a device or connection label containing `<script>` would execute. This is a stored XSS vector.

**Note:** SEC-1104-05 (IDOR on DiagramLayout mutations) is already tracked as **HT-053** in Ready for Development and is not included here.

**Source bugs:** SEC-1104-01, SEC-1104-02, SEC-1104-03, SEC-1104-04 (`findings-report-11-04-26.2.md`); BUG-TOPO-014 (`bug-report-12-04-26.2.md`).

## Acceptance Criteria

- Given an Admin sends `POST /api/import?confirm=true` with a malformed payload that triggers a DB IntegrityError, when the 422 response is returned, then the body is exactly `{"detail": "Import failed: data integrity violation"}` — no PostgreSQL table names, column names, or constraint names appear in the response.
- Given an unauthenticated HTTP client (no token), when `GET /api/health` is called, then the response body omits the `version` field entirely — it returns only liveness indicators (e.g. `{"status": "ok"}`). Authenticated users (any role) receive the full response including version.
- Given a Reader-role user, when `GET /api/system/stats` is called, then the `db_version` and `db_size_bytes` fields are absent from the response. Admin-role users receive those fields as before.
- Given a Contributor calls `GET /api/export` more than 3 times in one minute, when the 4th call arrives, then the server returns HTTP 429 Too Many Requests. Given anyone calls `POST /api/import?confirm=true` more than once per minute, then the second call returns HTTP 429.
- Given a connection exists with `label = '<script>alert(1)</script>'`, when the user right-clicks the edge and the delete confirmation dialog renders, then the script tag is displayed as literal escaped text in the dialog — `alert(1)` does not execute.

## Non-Goals (explicitly out of scope)

- Requiring authentication for Docker health check liveness probes (health endpoint *liveness* behavior unchanged — just version field omitted for unauthenticated callers).
- WAF or network-level rate limiting.
- Sanitizing all other free-text fields globally (scope is the specific confirm dialog rendering of `label`).
- SEC-1104-05 IDOR fix (tracked as HT-053).

## Notes for Architect / Engineer

**SEC-1104-01:** `src/api/routers/data_transfer.py` line 141 — replace `detail=f"Import failed: {exc.orig}"` with `detail="Import failed: data integrity violation"`.

**SEC-1104-02:** Two approaches — Architect-preferred option per the security report is Option A (require Reader role minimum) but this breaks Docker `HEALTHCHECK` probes that run before auth. **Recommended: Option B** — return `{"status": "ok"}` for unauthenticated callers; full stats including `version` for authenticated callers. This preserves Docker health check compatibility and removes version disclosure.

**SEC-1104-03:** `src/api/routers/system.py` and `src/services/system_service.py` — gate `db_version` and `db_size_bytes` behind `Role.Admin` check, matching the existing pattern for the `users` field in the same endpoint.

**SEC-1104-04:** `src/api/routers/data_transfer.py` — `@limiter.limit("3/minute")` on the export GET; `@limiter.limit("1/minute")` on the import POST. Import is Admin-only, export is Contributor+. The `slowapi` limiter is already initialized — decorators only.

**BUG-TOPO-014:** `src/ui/components/canvas_js_helpers.py` — the confirm dialog uses a string built from `edge.data('label')`. Apply `_htEscapeHtml()` (already defined in the codebase) to `raw_label` before inserting into the dialog HTML. Verify `_htEscapeHtml` handles `<`, `>`, `"`, `'`, and `&`.
