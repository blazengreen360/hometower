# HT-067: Make NiceGUI JS Bridge Scripts Singleton-Safe

**Status:** Done
**MoSCoW:** Must
**Kano:** Basic — duplicated document-level listeners create runaway event storms and backend lag in long-lived sessions
**Phase:** 1 (Hometower)
**Size:** S
**Shipped:** 13 April 2026

## Job-to-be-Done

As a long-session topology user, I want page revisits to not stack duplicate JS bridge listeners, so that selecting devices and edges keeps emitting exactly one event back to Python.

## Context

**BUG-1103-01 (High)** identifies a client-side leak in bridge scripts injected with `ui.add_body_html()`. Components such as `device_detail_panel_bridge.py` and `connection_detail_panel.py` register `document.addEventListener(...)` handlers without singleton guards. NiceGUI's SPA-like transitions keep the browser document alive, so re-entering the topology page re-injects identical listeners.

Impact: selecting one node or edge can emit many duplicate Python bridge events, causing UI lag and backend message amplification over time.

**Source bug:** BUG-1103-01 (`doc/bugs/bug-report-11-04-26.3.md`).

## Acceptance Criteria

- Given a bridge script is injected via `ui.add_body_html()`, when the page is visited a second time in the same browser session, then the script detects prior initialization and returns early rather than registering duplicate listeners.
- Given the user navigates to `/topology`, away, and back 10 times, when they click a device node once, then exactly one `panel_select`-style event is emitted back to Python.
- Given the same navigation loop, when they click a connection edge once, then exactly one connection-detail selection event is emitted back to Python.
- Given singleton guards are added, when the full verification gate runs, then pytest, mypy, docker build, and relevant UI tests all pass.

## Non-Goals (explicitly out of scope)

- Refactoring all injected JS into bundled static assets.
- Changing the socket/message protocol between JS and Python.
- Redesigning the device or connection detail panels.

## Notes for Architect / Engineer

- Apply the standard guard pattern at the top of each injected IIFE: `if (window._<name>Init) return; window._<name>Init = true;`
- PM memory reminder: JS scope isolation has already caused Code-Reviewer blockers. Define window-scoped guards explicitly and avoid closure-only flags that disappear across separately injected script blocks.
- Audit any other `ui.add_body_html()` bridge scripts touched by the same navigation flow, not just the two named in the report, if they use document-level listeners.
