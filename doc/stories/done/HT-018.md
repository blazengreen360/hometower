# HT-018: Device Notes Field

**Status:** Done
**MoSCoW:** Must
**Kano:** Basic — users expect a free-text area to annotate devices with setup details, quirks, or reminders
**Phase:** 1 (Hometower)
**Size:** XS (< 1 day)

## Job-to-be-Done
As a homelab owner, I want to add free-text notes to any device so that I can record setup details, troubleshooting history, or reminders without creating custom fields for one-off information.

## Context
HT-002 delivered device CRUD with core fields (name, type, IP, MAC, OS). Users immediately need a place to jot down unstructured information — "runs Plex, reboot monthly", "BIOS updated 2026-03-15", etc. A dedicated `notes` field (max 5000 chars) covers this without polluting custom fields (HT-007) with throwaway data.

## Acceptance Criteria
- Given I am a Contributor, when I `POST /api/devices` with a `notes` field (up to 5000 characters), then the device is created with notes persisted
- Given I am a Contributor and a device exists, when I `PATCH /api/devices/{id}` with `{"notes": "updated text"}`, then the notes field is updated
- Given I send notes exceeding 5000 characters, when I `POST` or `PATCH`, then I receive a 422 validation error
- Given I omit the `notes` field, when I create a device, then `notes` defaults to `null`
- Given a device has notes, when I `GET /api/devices/{id}`, then the response includes the `notes` field

## Non-Goals (explicitly out of scope)
- Rich text / Markdown rendering in notes (plain text only in v1)
- Notes history or versioning
- Notes on connections or locations (device-only for now)
- Full-text search across notes (covered by HT-020)
