# HT-019: Admin User Panel

**Status:** Completed
**MoSCoW:** Must
**Kano:** Basic — if the admin can't create accounts for family members or change roles, multi-user is broken.
**Phase:** 1 (Hometower)
**Size:** M (2-3 days)

## Job-to-be-Done
As an admin, I want a user management panel so that I can create accounts for household members, assign roles, and revoke access when someone no longer needs it.

## Context
HT-001 ships the first admin via env vars on first boot, but there's no way to create additional users or change roles through the UI. This story adds a Settings → Users page for Admins only.

## Acceptance Criteria
- Given I am an Admin, when I navigate to Settings → Users, then I see a table with columns: username, email, role, created_at, and action buttons (edit, delete)
- Given I click "Add User", when the modal opens, then I can fill in username, email, password, and role (dropdown: Admin, Contributor, Reader)
- Given I submit a valid new user form, when the `POST /api/users` completes, then the user appears in the table and can log in immediately
- Given I submit a new user with an email that already exists, when the API responds, then I see a 409 error: "Email already in use"
- Given I click "Edit" on a user, when the modal opens, then I can change their role (dropdown) and optionally set a new password (leave blank to keep current)
- Given I change a user's role from Contributor to Reader, when the change saves, then their next API call uses the new role (JWT re-issued on next login; existing JWT continues with old role until expiry)
- Given I click "Delete" on a user, when the confirmation dialog appears and I confirm, then the user is deleted and can no longer log in
- Given I try to delete my own account, when the API processes it, then it returns HTTP 400: "Cannot delete your own account"
- Given I try to delete the last Admin, when the API processes it, then it returns HTTP 400: "Cannot delete the last admin user"
- Given I am a Contributor or Reader, when I navigate to Settings → Users, then I am redirected to `/topology` with toast: "Admin access required"
- Given I am an Admin, when I `GET /api/users`, then I receive all users (password_hash is never included in the response)

## Non-Goals (explicitly out of scope)
- Self-service profile editing (users changing their own email/password) — Could-have for later
- User groups or teams — Phase 2 (LT-004)
- LDAP/SSO user provisioning — Phase 2 (LT-008)
- Avatar or profile picture
- User activity log
- Invite-by-email flow

## Open Questions
None — CRUD semantics and the self-delete/last-admin guards are confirmed.

## Notes for Architect / Engineer
- Router: `src/api/routers/users.py` — `GET /api/users`, `POST /api/users`, `PATCH /api/users/{id}`, `DELETE /api/users/{id}`
- Service: `src/services/user_service.py` — orchestrates user CRUD, enforces self-delete and last-admin guards
- Repository: `src/repositories/user_repository.py` already exists — extend with `count_by_role(role)` for last-admin check
- Response schema: `UserResponse` must exclude `password_hash` — use a separate Pydantic model that omits it
- Password field on create: hash via `hash_password()` from `src/utils/auth.py` before storing
- Password field on edit: optional — if blank, don't update `password_hash`
- UI: `src/ui/pages/settings_users.py` — NiceGUI table + modal (create/edit share a modal with mode toggle)
- RBAC: all endpoints require `Role.Admin`
- The "role change takes effect on next login" behavior is inherent to JWT — document this in the UI with a note: "Role changes apply on the user's next login"
