# HT-022: Networks / VLANs / Subnets

**Status:** Done
**MoSCoW:** Must
**Kano:** Basic — homelabbers think in network segments. "What's on VLAN 20?" is the second most natural question after "where is device X?" Without a Network entity, the topology diagram can't represent the network layer.
**Phase:** 1 (Hometower)
**Size:** L (5-6 days)

## Job-to-be-Done
As a homelab owner with multiple VLANs and subnets, I want to define my network segments and assign devices to them so that my inventory answers "which devices are on my IoT VLAN?" and "what IP range does my management network use?"

## Context
Real homelabs are segmented. A typical setup has 4-8 VLANs: management, trusted, IoT, guest, DMZ, storage, etc. Each VLAN maps to a subnet (e.g., VLAN 20 = 10.0.20.0/24). Devices live on one or more of these networks — a router lives on all of them, a NAS might be on storage + trusted.

Today, a Device has a single `ip` field. That's insufficient: a Proxmox host might have `10.0.10.5` on management, `10.0.20.5` on storage, and `10.0.30.5` on VM traffic. This story introduces a `Network` entity and a `DeviceNetwork` join table that captures which device has which IP on which network.

The existing `ip` field on Device remains as a "primary IP" convenience field. Networks are the full picture.

Note: `DeviceType` currently includes `VLAN` and `Subnet` values. Those will be deprecated in favour of the proper Network entity — the migration plan is in the engineer notes.

## Acceptance Criteria

### Data model
- Given I `POST /api/networks` with `{name: "Management", vlan_id: 10, cidr: "10.0.10.0/24", gateway: "10.0.10.1", description: "Management traffic", color: "#3b82f6"}`, then the network is created
- Given I `POST /api/networks` with `cidr: "not-a-cidr"`, then I receive HTTP 400: "Invalid CIDR notation"
- Given I `POST /api/networks` with `vlan_id: 5000`, then I receive HTTP 400: "VLAN ID must be between 1 and 4094"
- Given a network named "Management" exists (case-insensitive), when I create another with the same name, then I receive HTTP 409
- Given I `DELETE /api/networks/{id}` on a network with device associations, then I receive HTTP 400: "Network has devices assigned — remove them first"

### Device-network association
- Given a device and a network exist, when I `POST /api/devices/{device_id}/networks` with `{network_id, ip_address: "10.0.10.5"}`, then the association is created
- Given I assign a device to a network with `ip_address: "10.0.10.5"` but the network's CIDR is `10.0.20.0/24`, then I receive HTTP 400: "IP 10.0.10.5 is not within subnet 10.0.20.0/24"
- Given a device is already on a network, when I try to assign it again, then I receive HTTP 409: "Device is already on this network"
- Given I `GET /api/devices/{id}?include=networks`, then the response includes a `networks` array with each network's name, VLAN ID, CIDR, and the device's IP on that network
- Given I `GET /api/networks/{id}?include=devices`, then the response includes a `devices` array with each device's name, type, and IP on this network
- Given I `DELETE /api/devices/{device_id}/networks/{network_id}`, then the association is removed

### Canvas integration
- Given networks exist, when the View Designer canvas renders in edit or view mode, then a "Networks" panel (color-coded list) appears in the left sidebar below the stencils panel
- Given I toggle a network on in the sidebar, when the canvas updates, then devices on that network are highlighted with the network's color as a border or glow
- Given I toggle multiple networks on, when the canvas renders, then devices on multiple selected networks show stacked color indicators

### Inventory integration
- Given I am on the inventory list (HT-009), when a device belongs to networks, then the networks column shows color-coded badges (e.g., "Mgmt", "IoT")

## Non-Goals (explicitly out of scope)
- IP address management (allocation, conflict detection, usage grid) — that's HT-024
- DNS records or hostname resolution
- Network topology discovery (traceroute, LLDP, CDP) — Phase 2
- Firewall rules or ACLs between networks
- DHCP range tracking
- Network performance monitoring or traffic stats
- Automatic VLAN assignment based on device type

## Open Questions
None — Network entity with CIDR, VLAN ID, and device join table is confirmed. The Architect should decide whether the `DeviceType.VLAN` and `DeviceType.Subnet` enum values are removed or just deprecated in the migration.

## Notes for Architect / Engineer

### Data model
- `src/models/network.py`: `Network(id, name, vlan_id: int | None, cidr: str, gateway: str | None, description: str | None, color: str, created_at, updated_at)`
- `src/models/device_network.py`: `DeviceNetwork(device_id FK, network_id FK, ip_address: str, created_at)` — composite PK on `(device_id, network_id)`
- Domain: `src/domain/networks.py` — pure functions: `validate_cidr(cidr: str) -> IPv4Network | IPv6Network`, `validate_ip_in_subnet(ip: str, cidr: str) -> bool`, `validate_vlan_id(vlan_id: int) -> None`
- Use Python's `ipaddress` module for all CIDR/IP validation — same approach as the IPv6 fix in devices

### Migration
- Alembic migration: create `networks` table + `device_networks` join table
- Separate migration (or same): deprecate `DeviceType.VLAN` and `DeviceType.Subnet` — add a data migration that converts existing VLAN/Subnet devices to Network entities with best-effort field mapping
- The `ip` field on Device remains (primary/convenience IP); networks are the authoritative multi-homed source

### Canvas
- Network sidebar: NiceGUI panel listing all networks with color swatches and toggle checkboxes
- Highlight: use Cytoscape `cy.batch()` to add/remove a CSS class (e.g., `.network-highlight-{color}`) on matching nodes when a network is toggled
- Network badges on nodes: small colored dots at the bottom-right of each node showing which networks it belongs to

### API
- Router: `src/api/routers/networks.py` — full CRUD + device association sub-routes
- Service: `src/services/network_service.py` — CIDR validation, IP-in-subnet check, conflict detection
- Repository: `src/repositories/network_repository.py` + extend device repository for network includes
- RBAC: create/update/delete/associate require Contributor+; read for all authenticated users
