# HT-031: Bulk Operations in Inventory

**Status:** Done
**MoSCoW:** Should
**Kano:** Performance — the more devices a user has, the more painful one-at-a-time operations become. Bulk actions scale linearly with inventory size; without them, management effort scales quadratically.
**Phase:** 1 (Hometower)
**Size:** M (2–3 days)

## Job-to-be-Done
As a homelab owner with 50+ devices, I want to select multiple devices in the inventory table and perform batch actions (delete, tag, assign location, assign to container) so that reorganising my inventory doesn't require repeating the same action 30 times.

## Context
HT-009 built the inventory table. HT-010 built the device detail panel for single-device editing. But there's no multi-select capability. After initial setup — or when reorganising after adding a new hypervisor — users need to move groups of devices into a container (HT-021), assign them to a location, or tag them in bulk. Today every operation is one device at a time.

## Acceptance Criteria

### Selection
- Given I am on the inventory page as a Contributor or Admin, when I see the table, then each row has a checkbox on the left
- Given I click a row's checkbox, when it toggles, then the row is highlighted and a bulk action toolbar appears above the table showing "{N} selected"
- Given I click the header checkbox, when it toggles, then all visible rows are selected (or deselected if all were selected)
- Given I have filters active, when I select all, then only the filtered rows are selected — not the entire database
- Given I select devices and then change the filter/search, when the results update, then my selection is cleared and the bulk toolbar hides

### Bulk actions
- Given N devices are selected, when I click "Add Tag" in the bulk toolbar, then a dropdown with existing tags appears. Selecting a tag sends `POST /api/devices/{id}/tags` for each selected device. A progress indicator shows completion. A toast reports: "Tag '{name}' added to {N} devices"
- Given N devices are selected, when I click "Remove Tag" in the bulk toolbar, then a dropdown shows tags that are common to ALL selected devices. Selecting one sends `DELETE /api/devices/{id}/tags/{tag_id}` for each. Toast: "Tag '{name}' removed from {N} devices"
- Given N devices are selected, when I click "Set Location" in the bulk toolbar, then a dropdown of existing locations appears. Selecting one sends `PATCH /api/devices/{id}` with `{location_id}` for each. Toast: "Moved {N} devices to {location}"
- Given N devices are selected, when I click "Delete" in the bulk toolbar, then a confirmation dialog appears: "Delete {N} devices? This cannot be undone. Devices with active connections will be skipped." On confirm, each device is deleted. Toast: "Deleted {M} of {N} devices. {skipped} skipped (have connections)"
- Given a bulk action is in progress, when requests are executing, then a progress bar shows in the toolbar and the table rows update as each completes

### Error handling
- Given a bulk action partially fails (e.g. 3 of 10 deletions fail because of active connections), when the operation completes, then the toast reports the partial result: "Deleted 7 devices. 3 skipped: have active connections" and the failed rows remain selected for review
- Given the user loses network during a bulk action, when the failure is detected, then the progress bar stops and a toast reports how many succeeded before the failure

### RBAC
- Given I am a Reader, when I view the inventory table, then no checkboxes appear and no bulk toolbar is available

## Non-Goals (explicitly out of scope)
- Bulk editing of arbitrary device fields (name, IP, OS) — only tag, location, and delete in v1
- Bulk operations on the topology canvas (multi-select nodes) — inventory table only
- Bulk assign to container (HT-021 dependency) — add after HT-021 ships
- Undo for bulk actions
- Bulk export of selected devices to JSON

## Open Questions
None.

## Notes for Architect / Engineer
- **API pattern**: No new bulk endpoints needed — use sequential `PATCH`/`POST`/`DELETE` calls from the frontend, parallelised with `Promise.allSettled()` in JS or `asyncio.gather()` in Python. Keep it simple; 50 sequential PATCH calls take < 2 seconds.
- **Selection state**: Store selected device IDs in a Python `set` on the NiceGUI page. Clear on filter change or page navigation.
- **Toolbar component**: Create `src/ui/components/bulk_toolbar.py` rendering a horizontal bar with action buttons and a count badge. Show/hide based on selection count > 0.
- **Accessibility**: Checkboxes must be keyboard-navigable (Space to toggle). Bulk toolbar buttons should have ARIA labels describing the action and count.
