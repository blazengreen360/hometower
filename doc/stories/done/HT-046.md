# HT-046: Un-container — convert container back to plain node

**Status:** Done
**MoSCoW:** Must
**Kano:** Basic — absent: user cannot undo a container conversion without deleting children manually
**Phase:** 1 (Hometower)

## Job-to-be-Done
As a homelab author, I want to demote a container back to a plain node so that I can undo a mis-classification without destroying my topology structure by brute force.

## Context
HT-021 added "Convert to Container" via the canvas right-click menu. There is currently no inverse operation. If a user wants to undo this, their only option is to delete all children (removing them from the topology) and hope the container reverts. Users confirmed the destructive path (delete children) is acceptable, **but a confirmation dialog is required** so the action cannot be taken accidentally. An empty container (zero children) should convert back silently with no dialog.

## Acceptance Criteria
- Given a container node with children is right-clicked, when the user selects "Convert to Node", then a confirmation dialog appears: "This container has {N} child device(s). Converting it back to a node will remove them from this View. This cannot be undone. Continue?"
- Given the user confirms the dialog, then all immediate child nodes are removed from the canvas (their positions are cleared from this View's cytoscape_json) and the parent node loses its container class and `:parent` compound style.
- Given the user cancels the dialog, then no change is made to the canvas or the database.
- Given a container node has zero children, when "Convert to Node" is selected, then the node is immediately converted with no dialog.
- Given a plain (non-container) node, then "Convert to Node" does not appear in its right-click menu.
- Given layout autosave is active, when the conversion completes, then the View is autosaved within the normal autosave debounce window.

## Non-Goals (explicitly out of scope)
- Does not delete child devices from the inventory database — only removes them from this View's canvas.
- Does not re-parent grandchildren to the top level — if a child is itself a container with grandchildren, the entire subtree is removed from the View's canvas.
- Does not provide an undo/redo mechanism (that is HT-032).

## Notes for Architect / Engineer
- "Remove from canvas" means: remove those node IDs from the View's `cytoscape_json` elements array (no DB device deletion). Also remove any edges whose source or target is one of the removed nodes.
- The `PATCH /api/devices/{id}` call to clear `parent_id` is NOT needed — the container node itself stays in inventory; only the canvas layout data changes.
- The right-click context menu item lives in `src/ui/pages/topology.py`; the actual removal logic should be a new JS handler `ht:node-unconvert-container` in `canvas_container_events.py`.
- Confirmation dialog: use `window.confirm()` or the existing NiceGUI dialog component — keep it simple.
