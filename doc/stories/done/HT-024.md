# HT-024: IP Address Management View

**Status:** Done
**MoSCoW:** Should
**Kano:** Delighter — IP conflict debugging is the #1 "2 AM problem" for homelabbers. A visual IP grid that shows what's used, what's free, and what's conflicting is a killer feature that Netbox has and wikis don't.
**Phase:** 1 (Hometower)
**Size:** M (3-4 days)

## Job-to-be-Done
As a homelab owner, I want to see a visual map of IP usage across my subnets so that I can find free addresses, spot conflicts, and understand utilization at a glance.

## Context
Every homelabber has been bitten by IP conflicts. "Why is 10.0.10.42 not responding? Oh, I gave it to both the NAS and the new VM." The current Device model has a single `ip` field; HT-022 (Networks) adds proper subnet awareness with CIDR ranges and device-network associations. This story builds the **visual IPAM surface** on top of that data.

The IPAM view renders each network's subnet as a grid or table of IP addresses, colored by status: used (green), free (grey), gateway (blue), conflict (red). Clicking a used IP navigates to the device. This is a read-only view — IP assignment happens through device editing or network association.

Depends on: HT-022 (Networks/VLANs/Subnets).

## Acceptance Criteria

### Page
- Given I am authenticated, when I navigate to `/ipam`, then I see a page listing all networks (from HT-022) with their CIDR, VLAN ID, and a utilization bar (e.g., "23/254 used — 9%")
- Given I click on a network, when the detail view expands, then I see a grid of all IP addresses in the subnet, colored by status:
  - **Used** (green): IP assigned to a device via DeviceNetwork
  - **Free** (grey): no device assigned
  - **Gateway** (blue): matches the network's gateway field
  - **Conflict** (red): two or more devices claim the same IP on this network
  - **Reserved** (amber): first and last address of the subnet (network/broadcast)

### Grid behavior
- Given a /24 subnet (254 usable hosts), when the grid renders, then all 254 addresses are shown in a compact grid (16 columns × 16 rows)
- Given a /16 subnet (65,534 usable hosts), when the grid renders, then it shows a summary table grouped by /24 blocks with utilization percentages — not individual IPs (too many to render)
- Given I hover over a used IP cell, when the tooltip shows, then it displays: device name, device type, MAC address
- Given I click a used IP cell, when the navigation fires, then I go to `/topology?device_id={id}` with the device selected
- Given a conflict exists (two devices on the same IP), when the cell renders, then it's red with a tooltip listing both devices and a warning icon

### Search
- Given I type an IP address in the IPAM search bar (e.g., `10.0.10.42`), when the search runs, then the matching cell is highlighted and scrolled into view across all visible networks
- Given I type a device name, when the search runs, then all IPs belonging to that device are highlighted

### Statistics
- Given the IPAM page loads, when the header renders, then it shows aggregate stats: total networks, total IPs assigned, total conflicts, most-utilized network

## Non-Goals (explicitly out of scope)
- IP assignment from the IPAM view (assignment happens via device CRUD or network association — IPAM is read-only)
- DHCP lease tracking or integration
- DNS record display alongside IPs
- Ping sweep or live-reachability checks
- IP address reservation system (marking IPs as "planned" before assigning)
- IPv6 IPAM visualization (IPv4 grid model doesn't map to /64 subnets — defer to Phase 2)
- Subnet calculator tools

## Open Questions
None — the grid visualization approach and the dependency on HT-022 are confirmed.

## Notes for Architect / Engineer

### Backend
- New API endpoint: `GET /api/networks/{id}/ipam` — returns the full IP allocation map for a subnet
  - For /24 and smaller: return every IP with status (`free`, `used`, `gateway`, `conflict`, `reserved`) and optional device reference
  - For larger than /24: return /24 block summaries with counts
- Logic lives in `src/services/network_service.py` (or a dedicated `src/services/ipam_service.py` if it exceeds 250 lines)
- Domain: `src/domain/networks.py` — `build_ip_map(cidr: str, gateway: str | None, allocations: list[DeviceNetworkRead]) -> list[IpStatus]` — pure function, fully unit-testable
- Conflict detection: group by IP address, flag any IP with >1 device as `conflict`

### Frontend
- Page: `src/ui/pages/ipam.py` — network list with expandable IP grids
- Grid component: `src/ui/components/ip_grid.py` — CSS grid of colored cells, 16 columns
- Large subnet handling: for /16, render a nested grid of /24 blocks as summary cards
- Performance: for /24 (254 cells), render is trivial. For /16, summary mode keeps DOM under 300 elements.
- Design tokens: add IPAM-specific colors (used-green, free-grey, gateway-blue, conflict-red, reserved-amber) to `src/ui/design/tokens.py`

### Dependencies
- Requires HT-022 (Networks) to be shipped first — the Network entity, CIDR field, and DeviceNetwork join table are the data source
- Reads from `GET /api/networks` + `GET /api/networks/{id}?include=devices`

### RBAC
- Read-only page — available to all authenticated users
