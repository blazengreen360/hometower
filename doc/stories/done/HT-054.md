# HT-054: Human-readable timestamps in workspace, topology, and view tables

**Status:** Done
**MoSCoW:** Should
**Kano:** Performance — raw ISO 8601 strings (`2026-04-12T13:39:49.474932Z`) are machine-readable noise. Users scan "Last Modified" columns to answer "which workspace did I touch recently?" — a formatted date like "Apr 12, 2026, 1:39 PM" or relative label like "2 hours ago" answers that question instantly.
**Phase:** 1 (Hometower)
**Size:** S (half day)

## Job-to-be-Done
As a homelab owner, I want dates in my workspace, topology, and view tables shown in a human-readable format so that I can quickly identify recently modified items without mentally parsing ISO strings.

## Context
E2E sweep of HT-047 (12 Apr 2026) noted that all three hierarchy pages display raw ISO 8601 with microsecond precision in the "Last Modified" column — not useful at a glance.

Affected pages and fields:
- `/workspaces` — `last_modified` column in workspaces table
- `/workspaces/{id}` — `last_modified` column in topologies table

*(The `/workspaces/{id}/topologies/{id}` views table was removed by HT-057 — its timestamp formatting is no longer in scope.)*

The API returns ISO 8601. Formatting is purely a UI-layer concern — no API changes needed.

## Acceptance Criteria

### Format
- Given a timestamp from the API, when it is displayed in a table "Last Modified" / "Updated" column, then it shows in locale-appropriate human-readable form (e.g. "Apr 12, 2026, 1:39 PM").
- Given a timestamp from within the last 24 hours, the format options are: absolute (consistent), or relative ("2 hours ago") — either is acceptable, but the choice must be consistent across both pages.
- Given a timestamp that is `null` or missing (edge case: legacy layout with no `updated_at`), then the cell shows "—" rather than a blank or crash.

### Consistency
- Given all three hierarchy pages render timestamp columns, then the format is identical across all three (same function, not three separate implementations).

### Column label
- Given the views table currently uses "Last Modified", then the label stays "Last Modified" (no rename).

## Non-Goals (explicitly out of scope)
- Timezone picker / user preference (always display in browser local time)
- Relative timestamps that auto-refresh ("2 minutes ago" ticking)
- Date formatting on non-hierarchy pages (inventory, canvas — out of scope for this story)
- API changes

## UX Interaction Spec
- **Format string**: `MMM D, YYYY, h:mm A` — e.g. "Apr 12, 2026, 1:39 PM"
- **Tooltip**: On hover over a formatted timestamp, show the full ISO string as a tooltip for power users who want precision.
- **Shared helper**: Extract a `format_datetime(iso_str: str) -> str` pure function into a shared location (e.g. `src/ui/utils/formatting.py`) so all three pages use the same implementation.
- **Fitts**: Timestamp cells are read-only, no click affordance needed.

## Notes for Architect / Engineer
- Vue template approach: use a simple `formatDate(val)` method in the Quasar slot template, or handle it Python-side by formatting the string before populating `table.rows`. Python-side formatting is simpler (no JS needed) and consistent with the existing server-side rendering model.
- Python: `datetime.fromisoformat(iso_str.replace('Z', '+00:00')).strftime('%b %-d, %Y, %-I:%M %p')` — works on CPython 3.11+. The `%-d` / `%-I` directives are Linux-specific; use `{dt.day}` as fallback for portability.
- Alternatively, `arrow` library is clean: `arrow.get(iso_str).format('MMM D, YYYY, h:mm A')`. Check if `arrow` is already in `requirements.txt`.
- Column field name: change `"field": "last_modified"` / `"field": "updated_at"` to a new formatted field, OR format the value when building `table.rows`.
