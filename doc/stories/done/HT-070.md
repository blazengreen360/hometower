# HT-070: Restore Human-Readable Workspace Timestamps

**Status:** Done
**MoSCoW:** Should
**Kano:** Basic — timestamp readability is part of routine navigation and trust. Raw ISO strings in primary tables feel unfinished and regress previously shipped UX.
**Phase:** 1 (Hometower)
**Size:** S (1-2 days)

## Job-to-be-Done
As a user scanning workspace activity, I want Last Modified timestamps to be human-readable in workspace surfaces so that I can quickly understand recent changes without parsing raw ISO strings.

## Context
HT-054 shipped human-readable timestamps for workspace and topology hierarchy pages. The user simulation on 14 April 2026 found a regression on `/workspaces`: the Last Modified column is showing raw ISO timestamps such as `2026-04-12T23:11:18.073315Z` instead of the formatted browser-local display promised by HT-054.

This story restores the HT-054 contract on workspace-facing surfaces and locks it with regression coverage.

## Acceptance Criteria

### Workspace list formatting
- Given I visit `/workspaces`, when the table renders, then the **Last Modified** column displays browser-local human-readable timestamps in the HT-054 format
- Given a timestamp exists, when I hover the cell, then the raw ISO value remains available via tooltip if that pattern already exists
- Given a timestamp is missing or null, when the table renders, then the cell shows an em dash instead of raw placeholder text

### Consistency with existing hierarchy pages
- Given I open `/workspaces` and `/workspaces/{id}`, when both surfaces render timestamps, then they use the same formatting helper and visual rules
- Given the table sorts by Last Modified, when I sort ascending or descending, then sort behavior still follows the underlying raw timestamp rather than the formatted string

### Regression protection
- Given the unit/execution tests run, when workspace pages render timestamp data, then raw ISO strings do not leak back into the visible table cells
- Given HT-054 behavior is already covered elsewhere, when this story lands, then the new tests explicitly protect the `/workspaces` list regression path

## Non-Goals (explicitly out of scope)
- Relative-time strings like `3 hours ago`
- New timestamp columns or additional history/audit metadata
- Changes to backend timestamp generation semantics

## Open Questions
None.
