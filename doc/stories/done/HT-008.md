# HT-008: Geographic Map View with Leaflet.js

**Status:** Done
**MoSCoW:** Should
**Kano:** Delighter — most inventory tools don't have a map. For homelabbers with multi-site setups (off-site backup at parents' house, beach-house NAS, cabin weather station) this is unique territory.
**Phase:** 1 (Hometower)
**Size:** M (3-4 days)

## Job-to-be-Done
As a homelab owner with devices at more than one physical site, I want to see my infrastructure on a world map so that I can immediately grasp where every remote node lives.

## Context
HT-005 introduced the Location entity with `type=geo` and `lat`/`lng` fields. HT-008 renders those geo locations on a Leaflet.js map embedded in a NiceGUI page. Homelabbers with distributed infrastructure (VPS at a provider, off-site backup at a relative's house, LoRa weather node on a mountain) need a different visualisation than the topology canvas — the relevant question is "where is it" not "what connects to what".

OpenStreetMap tiles are used because they require no API key and have good dark-variant support. The map view has no edit mode — locations are created in Settings (HT-005). The map is a read-and-navigate surface.

## Acceptance Criteria
- Given I am authenticated and navigate to `/map`, when the page loads, then a full-viewport Leaflet map renders using OpenStreetMap tiles (dark variant in dark mode)
- Given I have geo locations with devices assigned, when the map renders, then a marker is drawn at each location's `(lat, lng)` with a tooltip showing location name and device count
- Given I have more than 10 geo locations close together, when the map renders at low zoom, then markers cluster together with a count badge; clusters expand as I zoom in
- Given I click a marker, when the click event fires, then a right-side slide-in panel opens showing the location name and the list of devices at that location
- Given I click a device in the slide-in panel, when the navigation happens, then I am taken to the topology canvas with that device selected and its detail panel open
- Given I have zero geo locations, when the map renders, then the empty state shows "No geographic locations yet — add a location with coordinates in Settings → Locations"
- Given the map is open in dark mode, when I inspect the tiles, then the dark tile variant is used and all controls (zoom, attribution) meet WCAG 2.1 AA contrast
- Given I zoom or pan the map, when I reload the page, then the view resets to fit-all-markers (pan/zoom state is not persisted)
- Given the Leaflet library fails to load (offline/blocked), when the page mounts, then the empty state shows a fallback list of geo locations as a plain table

## Non-Goals (explicitly out of scope)
- Adding or editing locations from the map — HT-005 handles that in Settings
- Drawing connections between geo locations (lines between sites) — v1 topology edges are on the canvas, not the map
- Routing or distance calculations between sites
- Custom tile providers or API-key-gated providers (OpenStreetMap only in v1)
- Heatmaps or density overlays
- Offline / self-hosted tile server (v1 hits tile.openstreetmap.org directly)

## Open Questions
None — OpenStreetMap is the confirmed tile provider and the data source is the existing Location entity from HT-005.

## Notes for Architect / Engineer
- Page at `src/ui/pages/map.py`
- Leaflet.js embedded via `ui.add_body_html()` + `ui.run_javascript()` in `src/ui/components/map_view.py` — follow the same pattern as `src/ui/components/canvas.py`
- Data source: `GET /api/locations?type=geo` (already defined in HT-005) — returns each location with a `devices` array via `?include=devices` query param — add this include to the HT-005 service if not already present
- Marker clustering via Leaflet.markercluster plugin — include in `src/ui/design/global.css` or load via CDN in `ui.add_head_html()`
- Slide-in panel is a NiceGUI `ui.right_drawer` or equivalent — click on JS marker → `ui.run_javascript` callback → Python handler fetches devices for that location and opens the panel
- Device row click in the panel → `ui.navigate.to('/topology?device_id={id}')` — HT-003 topology page must honour the `device_id` query param and pre-select that node (add this to HT-003 follow-up if missing)
- Dark-mode tile variant: use `https://{s}.basemaps.cartocdn.com/dark_all/{z}/{x}/{y}.png` (CartoDB dark, still OSM-based, no API key)
- No new backend endpoints required if HT-005 already supports `?include=devices` — otherwise extend the location service
- Accessibility: custom markers must be keyboard-navigable (Tab to cycle markers, Enter to open panel), per the UX-Designer accessibility rules
- File size budget: keep `src/ui/pages/map.py` ≤ 250 lines; extract any JS bootstrap into `src/ui/components/map_view.py`
- RBAC: read-only page, available to all authenticated users
