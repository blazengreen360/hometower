# HT-004: Device-to-Device Connections

**Status:** Done
**MoSCoW:** Must
**Kano:** Basic — a topology without edges is not a topology
**Phase:** 1 (Hometower)
**Size:** M (3-4 days)

## Job-to-be-Done
As a homelab owner, I want to draw connections between devices on the canvas so that I can document how my network is physically and logically wired.

## Context
HT-003 delivers nodes on the canvas. A homelab inventory is only useful if the user can express "switch-01 is uplinked to router-01 over fibre" and "proxmox-01 hosts container-03". This story adds the Connection entity, its backend CRUD, and the Cytoscape.js edge-drawing UX (click-drag from one node handle to another, pick a connection type, save).

`ConnectionType` already exists in `src/models/types.py`: `Ethernet`, `WiFi`, `Fibre`, `iSCSI`, `NFS`, `VM`, `Other`. The rendering contract for edges is defined in the UX-Designer agent spec: solid = physical (Ethernet/Fibre), dashed = virtual/logical (VM/iSCSI/NFS).

## Acceptance Criteria
- Given I am a Contributor and two devices exist, when I `POST /api/connections` with `{source_id, target_id, type, label}`, then a new connection is created and I receive its ID
- Given I am a Reader, when I `POST /api/connections`, then I receive a 403 Forbidden
- Given `source_id` equals `target_id`, when I `POST /api/connections`, then I receive a 400 error: "A device cannot connect to itself"
- Given a connection already exists between two devices with the same type, when I `POST /api/connections` with the same pair and type, then I receive a 409 Conflict: "Connection already exists"
- Given a connection exists, when I `DELETE /api/connections/{id}`, then it is removed and the canvas edge disappears on reload
- Given two device nodes are on the canvas, when I drag from one node's edge handle to another and release, then a modal asks for connection type + optional label and `POST /api/connections` is called on save
- Given connections exist for visible devices, when the topology page renders, then edges are drawn with solid line for Ethernet/Fibre and dashed line for VM/iSCSI/NFS
- Given I `GET /api/devices/{id}/connections`, then I receive every connection where the device is source or target, with the neighbour device's id and name included
- Given a device with connections is deleted via HT-002's rule, when the error fires, then the user sees which connections block deletion

## Non-Goals (explicitly out of scope)
- Bandwidth / throughput metadata on connections (not in v1)
- VLAN trunk configuration (covered by VLAN device type, not by Connection)
- Automatic link discovery via LLDP/CDP (Phase 2 / LightTower)
- Port-level connections (e.g. "eth0 on switch-01 to eth1 on router-01") — v1 models connections at the device level only
- Bulk edge creation / rubber-band edge drawing

## Open Questions
None — `ConnectionType` enum is frozen, rendering rules are in the UX-Designer spec, and HT-002 already defines the delete-block behaviour.

## Notes for Architect / Engineer
- SQLModel at `src/models/connection.py`: `id`, `source_id` (FK devices), `target_id` (FK devices), `type` (ConnectionType), `label` (Optional[str]), `created_at`
- Domain pure function `validate_connection(source_id, target_id, type)` in `src/domain/topology.py` — rejects self-loops, validates type enum
- Repository at `src/repositories/connection_repository.py` — methods: `create`, `get_by_id`, `get_by_device`, `delete`, `exists(source_id, target_id, type)` for the 409 check
- Service at `src/services/connection_service.py` — orchestrates domain validation + repository
- Router at `src/api/routers/connections.py` with Pydantic `ConnectionCreate`, `ConnectionRead`
- Add to `src/api/routers/devices.py`: `GET /api/devices/{id}/connections`
- Canvas edge drawing in `src/ui/components/canvas.py` — use Cytoscape's `edgehandles` extension; edge draw event calls `POST /api/connections` via `ui.run_javascript` → Python handler
- Edge styling data-driven via `line-style` mapping: `Ethernet|Fibre → solid`, `WiFi → dotted`, `iSCSI|NFS|VM → dashed`, `Other → solid`
- Alembic migration to create `connections` table; composite index on `(source_id, target_id, type)` for the 409 duplicate check
- Unique constraint at DB level mirrors the service-level 409 check
- RBAC: create/delete require `Role.Contributor` or higher; read is available to all authenticated users
