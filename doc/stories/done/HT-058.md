# HT-058: Autosave Conflict Visibility and Serialization

**Status:** Done
**MoSCoW:** Must
**Kano:** Basic — silent data loss causes dissatisfaction regardless of other quality
**Phase:** 1 (Hometower)
**Size:** M
**Shipped:** 13 April 2026

## Job-to-be-Done

As a Contributor, I want my topology layout changes to either save reliably or tell me immediately when they can't, so that I never lose diagram work without knowing about it.

## Context

Five related bugs in the autosave stack all share the same root failure mode: data is lost silently. BUG-TOPO-001 (Critical) races concurrent saves with the same `version`; BUG-TOPO-002 (High) drops large pending saves on tab-close via `keepalive` fetch; BUG-TOPO-003 (High) allows multiple `_htAutosaveTimer` references to be active simultaneously; IMPL-6.1 (High) dispatches `ht:autosave-conflict` but wires zero UI response; IMPL-6.2 (Medium) swallows network errors with a `console.error` and no retry.

All five bugs are in `src/ui/components/canvas_js_utils.py` and the autosave scheduling calls scattered across canvas event files.

**Source bugs:** BUG-TOPO-001, BUG-TOPO-002, BUG-TOPO-003 (`bug-report-12-04-26.2.md`), IMPL-6.1, IMPL-6.2 (`CANVAS_IMPLEMENTATION_BUG_REPORT_20260413.md`).

## Acceptance Criteria

- Given an in-flight autosave PATCH is pending, when `_htFlushAutosave()` is called again before the first resolves, then the second call is **queued** (not fired concurrently) — only one PATCH is in-flight at any moment.
- Given a 409 conflict response from the server, when the canvas receives it, then a persistent toast notification appears: *"Your layout was modified elsewhere — reload to sync"* and autosave suspends until the page is reloaded.
- Given the user closes the tab with a pending autosave whose payload exceeds 64KB, when `beforeunload` fires, then the browser shows a confirm: *"Save in progress — are you sure you want to leave?"* rather than silently attempting a `keepalive` fetch that may be dropped.
- Given a network error during autosave (DNS failure, timeout, 5xx), when the first attempt fails, then the client retries with exponential backoff (1s, 2s, 4s — three attempts), then shows a persistent toast: *"Autosave failed. Your changes may not be saved."*
- Given `scheduleAutosave()` is called from any combination of `dragfree`, `container collapse`, `unconvert`, or `draft cancel`, when all calls occur within 800ms, then exactly one `_htAutosaveTimer` reference exists at that moment — no stale timers from prior calls remain.

## Non-Goals (explicitly out of scope)

- Real-time multi-user collaborative editing / CRDT merging (Phase 2).
- Server-side ETag / If-Match semantics change.
- Surfacing *which* fields changed in the conflict.

## UX Interaction Spec

**Conflict toast:**
- Placement: top-center, persistent (not auto-dismissed), with a Reload button as the primary action.
- Fitts's Law: Reload button ≥ 32px tall, full-width of toast — this is a recovery action the user must deliberately choose.
- State: toast appears → autosave icon in toolbar (if any) turns to warning state → clicking Reload navigates to `window.location.reload()`.

**Save-failed toast:**
- Placement: bottom-right, auto-dismisses after 8s but stays if hovered.
- Text: "Autosave failed. Your changes may not be saved." with a Retry link.

**Unload confirm:**
- Standard browser `beforeunload` confirm — no custom UI possible; ensure the `event.returnValue` string is set for cross-browser support.

## Notes for Architect / Engineer

- Centralize autosave scheduling into a single `scheduleAutosave()` helper that atomically clears + sets `_htAutosaveTimer` and returns a cancel handle. All callers (canvas_js.py, canvas_container_events.py, canvas_draft_events.py) must route through this helper.
- `_htAutosaveInFlight` flag: set to `true` when PATCH fires, cleared in `.then()` and `.catch()`; queue a single pending flush deferred via `_htAutosavePending = true` flag.
- Payload size check before `beforeunload`: `JSON.stringify(getCanvasJson()).length > 65536` → block with confirm.
- `ht:autosave-conflict` CustomEvent already dispatched — wire a NiceGUI `ui.on()` listener or a JS document listener to `window._htNotify(...)`.
