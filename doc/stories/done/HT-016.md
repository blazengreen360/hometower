# HT-016: Canvas Keyboard Shortcuts

**Status:** Completed
**MoSCoW:** Should
**Kano:** Performance — every shortcut shaves seconds off repetitive canvas work. Power users expect them; absence feels sluggish.
**Phase:** 1 (Hometower)
**Size:** S (1-2 days)

## Job-to-be-Done
As a homelab owner building out my topology, I want keyboard shortcuts for common canvas actions so that I can work faster without reaching for context menus.

## Context
The topology canvas (HT-003) currently relies on right-click context menus and toolbar buttons for all actions. Keyboard shortcuts are the standard expectation for any diagramming tool (draw.io, Excalidraw, Lucidchart all have them). This story adds the core set.

## Acceptance Criteria
- Given a device node is selected on the canvas, when I press `Delete` or `Backspace`, then the device is deleted (same as the context menu "Delete" action) with the standard confirmation if it has connections
- Given a device node is selected, when I press `Ctrl+D` / `Cmd+D`, then the device is duplicated (same as context menu "Duplicate")
- Given one or more nodes are selected, when I press `Ctrl+A` / `Cmd+A`, then all nodes are selected
- Given I press `Escape`, when nodes are selected, then the selection is cleared; when the detail panel is open, then it closes
- Given I have performed an action (move, delete, create), when I press `Ctrl+Z` / `Cmd+Z`, then the last action is undone (single-level undo for node position changes only in v1)
- Given I press `Ctrl+S` / `Cmd+S`, when the save fires, then the current layout is saved (same as the Save Layout button) and the browser's default save-page dialog is suppressed
- Given I press `F` when no input is focused, then the canvas fits all nodes into view (`cy.fit()`)
- Given I am typing in the search bar or detail panel input, when I press Delete or any shortcut key, then the shortcut does NOT fire (shortcuts only active when canvas has focus)
- Given I am a Reader, when I press `Delete` or `Ctrl+D`, then nothing happens (write shortcuts are disabled for read-only roles)
- Given I hover over a toolbar button, when the tooltip renders, then it shows the keyboard shortcut (e.g., "Save Layout (Ctrl+S)")

## Non-Goals (explicitly out of scope)
- Multi-level undo/redo history (v1 is single-level undo for position only)
- Customisable key bindings
- Vim-style modal key bindings
- Shortcuts for the inventory list or map view (canvas only)
- Copy/paste across browser tabs

## Open Questions
None — the shortcut set above is the confirmed v1 scope.

## Notes for Architect / Engineer
- All shortcuts handled in `src/ui/components/canvas.py` or a new `src/ui/components/canvas_shortcuts.py`
- Use `document.addEventListener('keydown', handler)` injected via `ui.run_javascript()`
- Guard: check `document.activeElement.tagName` — skip if it's `INPUT`, `TEXTAREA`, or `[contenteditable]`
- Undo: store the last canvas state snapshot (positions only) and restore on Ctrl+Z; use `cy.nodes().positions()` to snapshot and bulk-set
- `Ctrl+S` prevention: `e.preventDefault()` to suppress browser save dialog
- OS detection: use `navigator.platform` or `e.metaKey` for Mac vs `e.ctrlKey` for Windows/Linux
- RBAC: pass the user's role into the JS context; write shortcuts check `window.htRole >= 'Contributor'` before executing
- Tooltip update: extend existing toolbar button tooltips to include shortcut text
