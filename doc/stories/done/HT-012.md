# HT-012: Export to JSON

**Status:** Completed
**MoSCoW:** Should
**Kano:** Basic for backup-conscious users — "Can I back up my data?" is a trust question. No export = no trust.
**Phase:** 1 (Hometower)
**Size:** S (1-2 days)

## Job-to-be-Done
As a homelab owner, I want to export my entire inventory to a single JSON file so that I have an offline backup I can store in git, a NAS, or anywhere I keep important config.

## Context
Hometower stores everything in PostgreSQL. If the container dies, the user loses their inventory unless they've set up pg_dump. This story provides a one-click JSON export that captures the full object graph: devices, connections, locations, tags, custom fields, diagram layouts, and networks/services (once those stories ship). The export format is the same one HT-013 (Import) will consume — they share a schema.

## Acceptance Criteria
- Given I am a Contributor or Admin, when I `GET /api/export`, then I receive a JSON file download containing all devices, connections, locations, tags, device-tag associations, custom fields, diagram layouts, networks, device-network associations, and services
- Given the export runs, when I inspect the JSON, then it includes a `version` field (e.g. `"1.0"`) and an `exported_at` ISO 8601 timestamp
- Given the export runs, when I inspect entity references, then all foreign keys use UUIDs (not database-internal IDs) so the file is portable across instances
- Given I have zero devices, when I export, then I receive a valid JSON with empty arrays (not an error)
- Given I am a Reader, when I `GET /api/export`, then I receive HTTP 403
- Given the export is large (500+ devices), when the response streams, then the server does not OOM — use streaming JSON serialization if the payload exceeds 10MB
- Given I trigger export from the UI (Settings → Export), when the download completes, then the filename is `hometower-export-{YYYY-MM-DD}.json`
- Given the export includes passwords or secrets, when I inspect the JSON, then user `password_hash` fields are **excluded** — only usernames and roles are exported

## Non-Goals (explicitly out of scope)
- CSV or YAML export formats (JSON only in v1)
- Selective export (e.g., "only devices tagged 'production'")
- Scheduled/automated exports — that's LT-006
- Export of user sessions or JWT tokens
- Binary attachments (no file attachments exist in v1)
- Database-level dump (pg_dump) — this is application-level export

## Open Questions
None — the export schema mirrors the data model, versioned at `1.0`.

## Notes for Architect / Engineer
- Router: `GET /api/export` in `src/api/routers/export.py` — returns `StreamingResponse` with `Content-Disposition: attachment`
- Service: `src/services/export_service.py` — assembles the full graph from all repositories in a single read transaction
- Schema: define `ExportSchema` Pydantic model in `src/models/export.py` with `version`, `exported_at`, and arrays for each entity type
- Explicitly exclude `User.password_hash` from the export — use a `UserExport` schema that omits it
- Sort entities by `created_at` for deterministic output (useful for diffing exports in git)
- RBAC: `require_role(Role.Contributor)` — Readers cannot export
- UI: add an "Export JSON" button in Settings page; triggers a browser download via `window.location.href = '/api/export'`
