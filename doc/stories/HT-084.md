# HT-084: Taxi-cab (Orthogonal) Edge Routing Styles

**Status:** Ready
**MoSCoW:** Should
**Kano:** Delighter — changes a messy diagram into a polished engineering schematic, significantly elevating the perceived quality of the tool.
**Phase:** 1 (Hometower)
**Size:** M

## Job-to-be-Done
As a user building complex network diagrams, I want to optionally route connections using 90-degree orthogonal styling (taxi-cab) so that my diagram looks like a cleanly organized technical schematic rather than a messy spider web.

## Context
Connections between devices are currently drawn as straight bezier curves (diagonal lines). In dense configurations, this visual noise makes the topology extremely difficult to interpret. High-end tools (Draw.io, Lucidchart) allow orthogonal line routing.
Design decision resolved in session: **Per-Connection Override**. Users will click an existing edge to open its properties panel, and select its routing style dynamically.

## Acceptance Criteria
- Given an edge connection on the topology canvas, when the user clicks the edge, then the Connection Detail Panel (HT-030) opens.
- Given the Connection Detail Panel is open, when viewing it, then a "Line Style" dropdown is available containing "Straight" (Bezier) and "Orthogonal" (Taxi-cab).
- Given the Line Style dropdown, when the user changes the selection, then the connection visually updates immediately on the canvas to use `taxi` or `bezier` curve style.
- Given a topology export or standard database fetch, when load data applies a style, then the style preference is persisted to the database and correctly applied the next time the topology loads.
- Given an orthogonal edge, when a user drags either of the connected nodes, then the edge routing dynamically maintains 90-degree angles.

## Non-Goals (explicitly out of scope)
- Global switch to apply orthogonal routing to all edges simultaneously.
- Interactive edge waypoints/handles (users cannot manually drag the corners of the 90-degree bends). Cytoscape's automatic taxi-cab routing is sufficient.
- Bundle routing (combining multiple parallel edges into one trunk).

## Business Invariants
- The routing style must be saved as a visual property on the layout JSON or Connection model, ensuring that reloads preserve the exact visual aesthetic the user established.
- Editing the curve style must create an Undo-stack entry, allowing the user to `Ctrl+Z` the style change.

## UX Interaction Spec
- **Dropdown Control**: Use a dense `<select>` input in the Connection Detail Panel, labeled "Routing Style". 
- **Value Persistence**: Maintain the exact layout visually; the edge route must not snap randomly when the topology gets refreshed.

## Notes for Architect / Engineer
- Cytoscape.js natively supports this via the `curve-style` CSS property: `'taxi'` (orthogonal lines) and `'bezier'` (curved/straight lines depending on nodes). 
- Add a tiny modification to `canvas_styles.py` to ensure the stylesheet dynamically maps the connection's data property to the Cytoscape CSS: `{'selector': 'edge', 'style': {'curve-style': 'data(routing_style)'}}`. If `data.routing_style` is empty or undefined, fallback to the default bezier.
- The property update flow follows standard updates: Panel change -> Python Service -> DB persist -> JSON push to cytoscape -> `cy.getElementById(edgeId).data('routing_style', 'taxi')`.
