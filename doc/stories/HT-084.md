# HT-084: Taxi-cab (Orthogonal) Edge Routing Styles

**Status:** Ready
**MoSCoW:** Should
**Kano:** Delighter — changes a messy diagram into a polished engineering schematic, significantly elevating the perceived quality of the tool.
**Phase:** 1 (Hometower)
**Size:** M

## Job-to-be-Done
As a user building complex network diagrams, I want to optionally route connections using 90-degree orthogonal styling (taxi-cab) so that my diagram looks like a cleanly organized technical schematic rather than a messy spider web.

## Context
Connections between devices are currently drawn as straight bezier curves (diagonal lines). In dense configurations, this visual noise makes the topology extremely difficult to interpret. High-end tools (Draw.io, Lucidchart) allow orthogonal line routing.

Two design decisions resolved in session:
1. **Per-Connection Override** — users click an existing edge to open its properties panel and select its routing style dynamically.
2. **Topology Default Style** — users set a preferred default routing style for the topology; all new connections inherit it without manual per-edge editing. This is distinct from a "global retroactive switch" (which remains a Non-Goal) — it only applies to connections created after the preference is set.

## Acceptance Criteria

Feature: Per-connection routing style
  Scenario: Changing a single edge's routing
    Given an edge connection on the topology canvas
    When the user clicks the edge
    Then the Connection Detail Panel (HT-030) opens
    And a "Routing Style" dropdown is available containing: Straight, Curved (bezier), Orthogonal (taxi-cab), and Rounded
    And changing the selection immediately updates the edge on the canvas
    And the choice persists to the database and survives topology reload

  Scenario: Orthogonal edge follows node drag
    Given a connection with "Orthogonal" routing style
    When the user drags either connected node
    Then the edge dynamically maintains 90-degree angles throughout the drag

Feature: Topology default routing style
  Scenario: Setting the default for new connections
    Given the user opens Topology Settings (gear icon in the canvas toolbar)
    When they change the "Default Routing Style" dropdown
    Then all new connections created in this topology use that style without needing manual per-edge configuration
    And existing connections are not changed (no retroactive rewrite)
    And the default is persisted to the topology record in the database

  Scenario: Per-edge override takes precedence
    Given a topology with default style set to "Orthogonal"
    When the user explicitly sets one edge to "Straight" via the Connection Detail Panel
    Then that edge renders as Straight while all other edges render as Orthogonal
    And the per-edge override survives topology reload

## Non-Goals (explicitly out of scope)
- Retroactive global switch to rewrite all existing edges to a new style simultaneously.
- Interactive edge waypoints/handles (users cannot manually drag the corners of the 90-degree bends).
- Bundle routing (combining multiple parallel edges into one trunk).

## Business Invariants
- Routing style is saved per-connection on the Connection model. Topology default is saved on the Topology record.
- Editing a routing style must create an Undo-stack entry (Ctrl+Z reverts the change).
- If a connection's `routing_style` field is null, it inherits the topology default. If the topology default is also null, fall back to `bezier`.

## UX Interaction Spec
- **Per-edge control**: Dense `<select>` dropdown in the Connection Detail Panel, labeled "Routing Style". Options: Straight | Curved | Orthogonal | Rounded.
- **Topology default**: A "Default Routing Style" select in the Topology Settings panel (same 4 options). Labeled "New connections use:".
- **Value Persistence**: Edge routes must not snap randomly on topology refresh — the stored style is the source of truth.

## Notes for Architect / Engineer
- Cytoscape `curve-style` values map to the 4 options: `straight` → Straight, `bezier` → Curved, `taxi` → Orthogonal, `round-segments` → Rounded.
- `canvas_styles.py`: add `{'selector': 'edge', 'style': {'curve-style': 'data(routing_style)'}}`. Null `routing_style` on the element falls through to the stylesheet default, which reads the topology default injected at canvas init time.
- `Connection` model: add `routing_style: Optional[str] = None` field. `Topology` model: add `default_routing_style: Optional[str] = None` field. Both need Alembic migration.
- At canvas init, inject the topology default as the base stylesheet rule: `{'selector': 'edge[!routing_style]', 'style': {'curve-style': topology.default_routing_style or 'bezier'}}`.
- Property update flow (per-edge): Panel change → Python service → DB persist → `cy.getElementById(edgeId).data('routing_style', value)`.
