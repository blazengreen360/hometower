# HT-017: Password Reset via CLI

**Status:** Completed
**MoSCoW:** Should
**Kano:** Basic for the "locked out" scenario — if the admin forgets their password and there's no reset path, the instance is bricked.
**Phase:** 1 (Hometower)
**Size:** XS (half day)

## Job-to-be-Done
As a homelab admin who forgot my password, I want to reset it from the server's command line so that I can regain access without wiping the database.

## Context
Hometower v1 has no email system, no "forgot password" link, and no external identity provider. If the admin loses their password, the only recovery path is the CLI. This story adds a management command that resets a user's password directly against the database.

## Acceptance Criteria
- Given I have shell access to the running container, when I run `docker compose exec api python -m src.cli reset-password --username admin@hometower.local --password newpass123`, then the user's password_hash is updated to the bcrypt hash of `newpass123`
- Given the username does not exist, when I run the command, then it exits with code 1 and prints "User not found: {username}"
- Given the new password is shorter than 8 characters, when I run the command, then it exits with code 1 and prints "Password must be at least 8 characters"
- Given the command succeeds, when I log in with the new password, then authentication works and a valid JWT is returned
- Given the command succeeds, when I inspect the output, then it prints "Password reset for {username}" and nothing else (no password echo)
- Given I run the command without `--password`, when prompted, then it reads the password from stdin (interactive mode) without echoing characters

## Non-Goals (explicitly out of scope)
- Web-based password reset flow
- Email-based reset tokens
- Password reset for non-admin users via the CLI (Admin can reset any user; this is intentional)
- Password complexity rules beyond minimum length

## Open Questions
None — CLI-only reset with bcrypt hashing is confirmed.

## Notes for Architect / Engineer
- CLI module: `src/cli.py` using `argparse` or `click` (keep it simple — `argparse` is stdlib)
- Reuse `hash_password()` from `src/utils/auth.py`
- Direct DB access: open a session via `src/utils/db.py`, query `User` by username, update `password_hash`, commit
- Interactive password input: use `getpass.getpass()` for no-echo stdin reading
- Entry point: `python -m src.cli` — add `__main__.py` or a `cli` subcommand
- No new dependencies required
- Tests: unit test the CLI argument parsing; integration test with a test DB that the password is actually updated and login works
