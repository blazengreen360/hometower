# HT-045: Extract FastAPI RBAC Dependency from Domain Layer

**Status:** Ready
**MoSCoW:** Should
**Kano:** Basic
**Phase:** 1 (Hometower)
**Size:** S

## Job-to-be-Done
As a **maintainer**, I want the domain layer to contain zero framework dependencies so that business rules remain independently testable and Code-Reviewer stops flagging architecture violations on every diff that touches RBAC.

## Context
`src/domain/rbac.py` currently contains two kinds of code:

1. **Pure domain logic** — `ROLE_HIERARCHY`, `can_perform(user_role, required_role)`. No I/O, no framework imports. This belongs in `src/domain/`.
2. **FastAPI dependency factory** — `require_role(required)`, which imports `fastapi.HTTPException` and `fastapi.Request`, constructs a `Depends`-compatible callable, and raises HTTP 403. This belongs in `src/api/`.

The module header even says "Pure Python — no I/O, no database, no network. Only imports from src/models/types.py" — but it imports FastAPI. This was flagged by Code-Reviewer during HT-027 approval and acknowledged as a pre-existing issue.

11 API routers import `require_role` from `src.domain.rbac`. One UI component (`auth_guard.py`) imports `can_perform` — that usage is correct (pure function).

## Acceptance Criteria
- Given `src/domain/rbac.py`, when I inspect its imports, then it contains **zero** imports from `fastapi` or any other web framework
- Given `src/api/dependencies/rbac.py` (or equivalent API-layer module), when a router uses `Depends(require_role(Role.Admin))`, then it imports from the API layer, not the domain layer
- Given `require_role()` in the API layer, when it checks permissions, then it delegates to `can_perform()` from `src/domain/rbac` (domain stays the source of truth for role hierarchy)
- Given the full test suite, when I run `pytest`, then all 843+ tests pass with zero import changes needed in test files (or test imports are updated accordingly)
- Given `mypy src/ --ignore-missing-imports`, then zero new type errors are introduced

## Non-Goals (explicitly out of scope)
- Refactoring other domain modules — only `rbac.py` is in scope
- Changing RBAC business rules or role hierarchy
- Adding new roles or permissions
- Modifying the auth middleware (`src/api/middleware/auth.py`)
