# HT-047: Workspaces, Topologies, and Views — 3-level navigation hierarchy

**Status:** Ready
**MoSCoW:** Must
**Kano:** Performance — more organisational structure = more satisfaction for users with multiple infrastructure environments
**Phase:** 1 (Hometower)

## Job-to-be-Done
As a homelab author, I want to organise my diagrams as named Topologies (e.g. "Home Lab") grouped inside Workspaces (e.g. "Home Projects"), where each Topology has multiple Views (e.g. Network, Services, Deployment), so that I can document the same infrastructure from different perspectives without losing context or creating duplicate inventories.

## Context
Currently `DiagramLayout` is a flat global list with no grouping and no concept of multiple perspectives on the same environment. This story introduces a **3-level hierarchy**:

```
Workspace  (organiser group, e.g. "Home Projects")
  └── Topology  (a subject, e.g. "Home Lab")  ← NEW entity
        └── View  (a canvas perspective, e.g. "Network")  ← rename of DiagramLayout
```

Devices are global inventory shared across all Views in all Topologies. A View is a manually-curated canvas: the user explicitly places devices and draws connections — it does not auto-load all devices. Views have independent canvas positions from one another. Device creation happens on the canvas via drag from a type palette (HT-051) and is published to global inventory explicitly; the View is the primary creation surface.

**Distinction from LT-004 (Phase 2 multi-workspace):** That story adds cross-user team access control. This story is single-user organisational grouping only.

## Acceptance Criteria

**Workspace level:**
- Given a user is logged in, when they click "Workspaces" in the top navigation, then they see a list of their Workspaces (name, topology count, last modified, actions: Rename, Delete).
- Given no Workspaces exist, then a "Default Workspace" is auto-created on first navigation.
- Given a user clicks "New Workspace", then a dialog prompts for a name and creates the Workspace.
- Given a user clicks a Workspace name, then they navigate to that Workspace's Topologies table.

**Topology level:**
- Given a user is on the Topologies table, it shows columns: Name, Views count, Tags, Last Modified, Actions (Open, Rename, Delete, Tag).
- Given a user clicks "New Topology", then a dialog prompts for a name and creates the Topology (with zero Views).
- Given a user clicks "Open" on a Topology, then they navigate to that Topology's Views table.
- Given a user clicks "Delete" on a Topology with Views, then a confirmation warns that all Views and their canvas data will be deleted.
- Given no Topologies exist in a Workspace, then a "Default Topology" is auto-created when the Workspace is created.

**View level:**
- Given a user is on the Views table for a Topology, it shows columns: Name, Last Modified, Actions (Open, Rename, Delete).
- Given a user clicks "New View", then a dialog prompts for a name and creates a new empty View (replacing the old "New Diagram Layout" flow).
- Given a user clicks "Open" on a View, then they navigate to the View Designer for that View (HT-048).
- Given a user clicks "Delete", then a confirmation appears; on confirm the View's canvas data is deleted (devices in global inventory are unaffected).
- Given no Views exist for a Topology, then a "Default View" is auto-created when the Topology is created.

**Migration:**
- Given existing `DiagramLayout` records, then migration creates one Default Workspace and one Default Topology for all existing layouts, assigns each layout as a View under that Topology.

**Search:**
- Given any list table has more than 10 rows, then search by name filters the list.

## Non-Goals (explicitly out of scope)
- No sharing of Workspaces, Topologies, or Views between users (Phase 2 / LT-004).
- No workspace-level RBAC beyond existing system roles.
- No canvas thumbnail previews in this story.
- No drag-and-drop reordering of rows.
- No Topology or View duplication/clone in this story.

## UX Interaction Spec
**Navigation flow:**
```
Top nav "Workspaces" → /workspaces (Workspace list)
  Click workspace name → /workspaces/{id} (Topology table)
    Click "Open" on topology → /workspaces/{wid}/topologies/{tid} (Views table)
      Click "Open" on view → /topology/{view_id} (View Designer — HT-048)
```

**Back navigation:** Each page shows a breadcrumb: `Workspaces > {workspace name} > {topology name}` so users can navigate up without the browser back button.

**Fitts's Law:** "New Workspace / New Topology / New View" button is the primary action — full-width or top-right, ≥44px height. Delete is in an overflow "⋯" menu on each row to prevent accidental clicks.

## Notes for Architect / Engineer
**Data model changes (migration required):**
- New `Workspace` model: `id` (UUID PK), `name` (str), `owner_id` (FK → User), `created_at`, `updated_at`.
- New `Topology` model: `id` (UUID PK), `name` (str), `workspace_id` (FK → Workspace), `tags` (JSON array, default `[]`), `created_at`, `updated_at`.
- Rename/alter `DiagramLayout` → add `topology_id` (UUID FK → Topology). The model may stay named `DiagramLayout` internally; the UI calls it "View". Add `tags` column here if topology-level tagging is insufficient.
- Migration order: create `workspaces` → create `topologies` → add `topology_id` to `diagram_layouts` → backfill (create Default Workspace, Default Topology per user, assign all existing layouts).
- `ON DELETE CASCADE`: deleting a Topology deletes all its Views (DiagramLayouts). Deleting a Workspace deletes all its Topologies (and their Views). Devices in global inventory are never touched.

**API changes:**
- `GET/POST /api/workspaces/`
- `GET/PATCH/DELETE /api/workspaces/{id}`
- `GET/POST /api/workspaces/{id}/topologies/`
- `GET/PATCH/DELETE /api/topologies/{id}`
- `GET/POST /api/topologies/{id}/views/`
- `GET/PATCH/DELETE /api/views/{id}` (or keep `/api/diagrams/{id}` with `topology_id` filter)
- Existing `/api/diagrams/` endpoints kept for backwards compat with canvas autosave; `topology_id` added as required field going forward.

**UI pages:**
- `src/ui/pages/workspaces.py` — Workspace list
- `src/ui/pages/workspace_detail.py` — Topology table for one Workspace
- `src/ui/pages/topology_detail.py` — Views table for one Topology
- Navigation sidebar: "Workspaces" replaces the existing flat "Diagrams/Layouts" item.
