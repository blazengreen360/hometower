# HT-034: Health Check Endpoint

**Status:** Ready
**MoSCoW:** Must
**Kano:** Basic — every self-hosted tool in a homelabber's stack gets monitored (Uptime Kuma, Healthchecks.io, Docker healthcheck). No health endpoint means Hometower is a black box. This is table stakes.
**Phase:** 1 (Hometower)
**Size:** XS (half day)

## Job-to-be-Done
As a homelab owner running a monitoring stack, I want Hometower to expose a health endpoint so that Uptime Kuma / Healthchecks.io / Docker can verify the app is alive and the database is reachable.

## Context
The Docker Compose file uses `pg_isready` to healthcheck the database container, but the `api` service has **no healthcheck**. There is no `/health` or `/api/health` endpoint. If the FastAPI process hangs or the DB connection pool is exhausted, Docker doesn't know, and monitoring tools can't detect the failure.

## Acceptance Criteria
- Given the app is running and the database is reachable, when I `GET /api/health`, then I receive HTTP 200 with body: `{"status": "healthy", "version": "1.0.0", "database": "connected", "uptime_seconds": 12345}`
- Given the database is unreachable (connection refused or timeout), when I `GET /api/health`, then I receive HTTP 503 with body: `{"status": "unhealthy", "version": "1.0.0", "database": "disconnected", "uptime_seconds": 12345}`
- Given the endpoint is called, when the DB check runs, then it executes `SELECT 1` — not a full table scan or expensive query
- Given any user (authenticated or not), when they call `GET /api/health`, then the endpoint responds — no JWT required (public endpoint)
- Given the health endpoint exists, when I inspect the Docker Compose `api` service, then it has a `healthcheck` directive: `curl -f http://localhost:8080/api/health || exit 1`
- Given the health response includes `version`, when I inspect it, then the version string comes from a single source of truth (e.g. `src/__version__.py` or `pyproject.toml`)

## Non-Goals (explicitly out of scope)
- Detailed subsystem checks (Redis, external APIs, disk space) — DB connectivity is sufficient for v1
- Prometheus metrics endpoint (`/metrics`)
- Response time percentiles or request counters
- Readiness vs liveness probe distinction (single endpoint serves both)
- Version auto-increment from git tags or CI

## Open Questions
None.

## Notes for Architect / Engineer
- **Router**: Add `GET /api/health` in `src/api/routers/health.py`. Register in `app.py`.
- **Auth exclusion**: Add `/api/health` to `EXCLUDED_PATHS` in `src/api/middleware/auth.py`.
- **DB check**: Open a session, run `session.exec(text("SELECT 1"))`, catch `Exception` → return 503.
- **Uptime**: Record `_start_time = datetime.now(timezone.utc)` at module import or in the lifespan handler. Compute `uptime_seconds` on each request.
- **Version**: Create `src/__version__.py` with `__version__ = "1.0.0"`. Import in the health router.
- **Docker healthcheck**: Add to `docker-compose.yml` under the `api` service:
  ```yaml
  healthcheck:
    test: ["CMD", "curl", "-f", "http://localhost:8080/api/health"]
    interval: 30s
    timeout: 5s
    retries: 3
  ```
