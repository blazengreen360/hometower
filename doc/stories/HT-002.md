# HT-002: Device CRUD Operations (Backend)

**Status:** Ready
**MoSCoW:** Must
**Phase:** 1 (Hometower)
**Size:** M (3-4 days)

## Job-to-be-Done
As a homelab owner, I want to create, read, update, and delete devices in my inventory so that I can maintain an accurate record of my infrastructure.

## Context
Devices are the core entity. Every node on the topology canvas or map marker corresponds to a Device record in PostgreSQL. This story covers the backend API and database layer only — UI comes in HT-003 (topology canvas) and HT-009 (inventory list).

Device types: Server, Switch, Router, NAS, UPS, SBC, Workstation, VM, LXC Container, Docker Container, Application, VLAN, Subnet.

## Acceptance Criteria
- Given I am authenticated as a Contributor, when I `POST /api/devices` with `{name, type, ip, mac, os, notes, location_id}`, then a new device is created and I receive its ID and `created_at` timestamp
- Given I am authenticated as a Reader, when I `POST /api/devices`, then I receive a 403 Forbidden error
- Given a device exists, when I `GET /api/devices/{id}`, then I receive the full device record including all fields and timestamps
- Given a device exists and I am a Contributor, when I `PATCH /api/devices/{id}` with `{name: "New Name"}`, then the device name is updated and `updated_at` is refreshed
- Given a device exists and I am a Contributor, when I `DELETE /api/devices/{id}`, then the device is soft-deleted (or hard-deleted if no connections exist) and returns 204 No Content
- Given a device has connections, when I `DELETE /api/devices/{id}`, then I receive a 400 error: "Cannot delete device with active connections"
- Given I `GET /api/devices`, then I receive a paginated list of all devices (default 50 per page)

## Notes for Architect / Engineer
- SQLModel schema at `src/models/device.py` with all fields: `id`, `name`, `type`, `ip`, `mac`, `os`, `notes`, `location_id`, `created_at`, `updated_at`
- `DeviceType` enum at `src/models/types.py` (Server, Switch, Router, NAS, UPS, SBC, Workstation, VM, LXC, Docker, Application, VLAN, Subnet)
- Repository at `src/repositories/device_repository.py` with methods: `create()`, `get_by_id()`, `get_all()`, `update()`, `delete()`
- Service at `src/services/device_service.py` orchestrates validation and repository calls
- Router at `src/api/routers/devices.py` with Pydantic schemas for request/response validation
- IP and MAC validation in domain layer (`src/domain/devices.py`)
- Foreign key to `locations` table (nullable — devices can exist without a location)
- Index on `name` and `type` columns for search performance
- Alembic migration to create `devices` table
