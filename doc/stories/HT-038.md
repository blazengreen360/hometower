# HT-038: Graceful Session Expiry Handling

**Status:** Ready
**MoSCoW:** Must
**Kano:** Basic — users hit JWT expiry every day. A silent redirect while mid-edit is confusing and can cause data loss. Every production web app handles this; its absence is a defect, not a missing feature.
**Phase:** 1 (Hometower)
**Size:** S (1 day)

## Job-to-be-Done
As a Hometower user, I want to be told clearly when my session has expired and be redirected to login without losing context, so that I never wonder why my save failed or my page went blank.

## Context
JWT tokens expire after 24 hours (`ACCESS_TOKEN_EXPIRE_MINUTES=1440` in auth). Currently, when a token expires mid-session:

1. API calls return `401 Unauthorized` silently.
2. UI pages with `redirect_if_unauthenticated()` redirect to `/login` without explanation.
3. Any unsaved work is lost — no warning, no "your session expired" message.
4. After re-login, the user lands on `/topology` (or `/` after HT-026) instead of the page they were on.

### Desired behaviour
- Intercept 401 responses from the API → show a "Session expired" toast (or overlay)
- Redirect to `/login?expired=1&next=/previous-page`
- Login page shows "Your session expired. Please sign in again."
- After successful re-login, redirect to the `next` URL instead of the default

## Acceptance Criteria

### Detection
- Given my JWT has expired, when any API call returns `401`, then the UI intercepts the response before it hits the calling component
- Given the 401 is due to token expiry (not invalid credentials), when the interceptor fires, then it does **not** retry the request — it triggers the expiry flow

### User notification
- Given a session expiry is detected, when the flow triggers, then a full-screen overlay appears: "Your session has expired. Please sign in again." with a "Sign In" button
- Given the overlay is showing, when I click "Sign In", then I am redirected to `/login?expired=1&next={current_path}`

### Login page
- Given I land on `/login` with query param `expired=1`, when the page renders, then an info banner shows: "Your session expired. Please sign in again."
- Given I land on `/login` without `expired=1`, when the page renders, then no banner is shown

### Return-to-page
- Given I log in successfully after expiry, when `next` query param is present and is a valid internal path, then I am redirected to that path instead of the default dashboard
- Given the `next` param is missing, empty, or an external URL, when login succeeds, then I am redirected to the default route (`/topology` or `/` post-HT-026)

### Edge cases
- Given multiple API calls fail with 401 simultaneously, when the interceptor fires, then the expiry overlay shows only once — no duplicate overlays or multiple redirects
- Given I am on the login page and my (non-existent) token is expired, when the page loads, then no expiry overlay fires — login page is exempt

## Non-Goals (explicitly out of scope)
- Token refresh / sliding sessions — v1 tokens are single-use, 24h fixed expiry
- "Remember me" checkbox or persistent sessions
- Warning before expiry ("Your session expires in 5 minutes")
- Saving unsaved form state across session boundaries

## Open Questions
None.

## Notes for Architect / Engineer
- **Intercept layer**: Add a JavaScript-level `fetch` wrapper or Cytoscape/NiceGUI response handler that checks for 401 status codes. Since NiceGUI uses a WebSocket for UI updates, also handle the case where the FastAPI middleware rejects a WS message.
- **Auth guard update**: `redirect_if_unauthenticated()` in `auth_guard.py` currently does a hard redirect. Update it to pass `?expired=1&next=` when the token was present but invalid/expired (vs. absent entirely, which is a first visit).
- **Security**: Validate that `next` param is a relative path (starts with `/`) and does not contain `://` to prevent open redirect.
