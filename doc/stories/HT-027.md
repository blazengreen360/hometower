# HT-027: Premium Design System & Theme Engine

**Status:** Ready
**MoSCoW:** Must
**Kano:** Performance / Delighter hybrid — a polished UI directly increases perceived quality and trust. Homelabbers compare Hometower to Netbox, Portainer, Unraid — all have strong visual identity. Without this, Hometower looks like a prototype.
**Phase:** 1 (Hometower)
**Size:** L (3 days)
**Depends on:** HT-026 (App Shell) must ship first — this story styles the shell.

## Job-to-be-Done
As a homelab owner, I want Hometower to look and feel like a premium, modern infrastructure tool — polished enough that I'm proud to show it to friends and on r/homelab — so that using it feels like a reward rather than a chore.

## Context
The current UI uses a single hardcoded dark palette in `src/ui/design/tokens.py` with no transitions, no visual hierarchy beyond font size, and no theme switching. Every page independently applies `background-color` and `color` inline. The result is functional but flat — it looks like a weekend hackathon, not a product.

This story introduces:
1. **A theme engine** — multiple named themes (dark, light, midnight) with runtime switching
2. **An expanded design token system** — elevation (shadows), border radii, transitions, gradients, opacity levels
3. **Premium visual language** — glassmorphism sidebar, subtle gradients, micro-animations, card hover effects, typographic hierarchy
4. **Component-level CSS overhaul** — every existing page and component updated to use the new tokens

### Design Language: "Clean Ops"
Hometower's visual identity should feel like a **premium SaaS tool for infrastructure** — clean, airy, and professional. Not a dark hacker terminal, not a generic admin panel. Think: the attached workflow-builder inspiration — minimal chrome, generous whitespace, card-based surfaces, and clear typographic hierarchy.

Key traits:
- **Airy whitespace** — generous padding inside cards (20–24px), comfortable spacing between elements (16–24px gaps). The UI should breathe, never feel cramped.
- **Card-based surfaces** — every distinct content area (sidebar items, stat cards, detail panel sections, palette entries) is a clean rounded card with a subtle 1px border and minimal shadow. No heavy drop-shadows or glassmorphism.
- **Sidebar as a clean panel** — solid surface background (not frosted glass), items rendered as card-like rows with an icon on the left, title in medium weight, and an optional muted subtitle beneath. Active item gets an accent left border (3px) and tinted background. Clear visual grouping with section headers.
- **Collapsible sections** — the right-side detail panels (device detail, connection detail) use collapsible accordion sections with chevron toggles (e.g. "General Information ▾", "Network Settings ▾", "Tags ▾"). Sections expand/collapse with a smooth 200ms height transition.
- **Minimal header toolbar** — thin top bar (48px height) with: logo left, breadcrumb center, small icon-only toolbar buttons (save, undo, redo), user avatar + dropdown right. No heavy borders — just a subtle 1px bottom border.
- **Clean form layout** — form fields in detail panels have a label above, subtle border input below, consistent field widths. Dropdowns and selects match the input style. Chip/pill badges for tags and values use rounded backgrounds (9999px radius) with the relevant accent colour.
- **Smooth transitions** — all hover/focus/active states transition at 150–200ms ease. No jarring snaps. Card hover lifts by 1px (not 2px) with a slight shadow increase. Sidebar item hover tints the background.
- **Typography hierarchy** — Inter (or system font stack) with clear steps:
  - Page title: 20px, weight 600
  - Section header: 14px, weight 600, uppercase tracking 0.5px, muted colour
  - Body: 14px, weight 400
  - Caption/subtitle: 12px, weight 400, muted colour
  - Monospace values (IPs, MACs): `'Fira Mono'`, 13px
- **Consistent border radius** — 10px for cards and panels, 8px for inputs and buttons, 12px for modals, 9999px for pills/badges/chips
- **Node styling on canvas** — topology nodes render as clean rounded rectangles (matching the workflow-builder node style) with: coloured icon on the left, device name as title (14px medium), device type as subtitle (12px muted). Selected nodes get an accent border, not a glow halo.
- **Edge styling on canvas** — connections are clean curved lines (bezier) with subtle arrowheads. Labels sit on the line midpoint in a small white/surface-coloured pill to maintain readability over any background.

## Acceptance Criteria

Should not look like an AI design prototype or tool. Should look like a polished, cohesive product with a clear visual identity. The theme switcher should work flawlessly with no flashes of unstyled content or inconsistent states. 

### Theme engine
- Given I am authenticated, when I open the user menu in the header (from HT-026), then I see a "Theme" submenu with options: **Dark** (default), **Light**, **Midnight**
- Given I select "Light" theme, when the switch happens, then **all** UI surfaces, text, shadows, and accents update to the light palette within a single repaint — no partial/flickering state
- Given I set a theme, when I reload or navigate to another page, then the theme persists (stored in `app.storage.user['theme']`)
- Given I visit the login page (unauthenticated), when the page loads, then it uses the Dark theme (default for logged-out users)
- Given a new theme is selected, when CSS custom properties update, then Cytoscape.js node/edge styles also update to match (label colour, selection highlight, edge colour)

### Visual overhaul — sidebar & header
- Given the sidebar (from HT-026) renders, when I look at it, then it has a solid `bg-surface` background with a `1px solid {border}` right edge — clean panel, no frosted glass
- Given sidebar items render, when I look at them, then each item is a card-like row with: icon (20px, muted colour), title (14px medium), optional subtitle (12px muted) — matching the workflow-builder palette style
- Given I hover over a sidebar item, when the hover state activates, then the row background tints to `bg-surface-raised` with a smooth 150ms transition
- Given the active sidebar item renders, when I look at it, then it has a left accent bar (3px, accent colour) and a tinted `accent-glow` background — no other items have left bars
- Given the header bar renders, when I look at it, then it is 48px tall with a `1px solid {border}` bottom edge and no box-shadow — minimal and clean
- Given the header toolbar icons (save, undo, redo) render, when I look at them, then they are 32×32px icon-only buttons with rounded hover backgrounds (8px radius, `bg-surface-raised` on hover)

### Visual overhaul — cards & dashboard
- Given I am on the dashboard (from HT-026), when stat cards render, then each card has `border-radius: 10px`, a `1px solid {border}` outline, and `shadow-sm` only — clean and subtle, not heavy elevation
- Given I hover over a stat card, when the hover state activates, then the card lifts by 1px (`transform: translateY(-1px)`, shadow transitions from `shadow-sm` to `shadow-md`, 150ms ease)
- Given device-type breakdown renders in the stat card, when I see the mini bars, then each bar segment uses the existing `DEVICE_TYPE_COLORS` from `tokens.py`

### Visual overhaul — detail panels
- Given I click a device or connection on the canvas, when the right-side detail panel opens, then it uses collapsible accordion sections (e.g. "General Information ▾", "Network ▾", "Tags ▾", "Custom Fields ▾") with smooth 200ms height transitions
- Given a section is collapsed, when I click its header, then it expands to show its content with a chevron rotation animation
- Given form fields render inside a section, when I inspect them, then labels sit above inputs, inputs have `1px solid {border}` borders with `border-radius: 8px`, and field widths are consistent within each section
- Given tag or value chips render in the detail panel, when I see them, then they are rounded pills (`border-radius: 9999px`) with a tinted background matching the tag's colour at 15% opacity and the tag colour as text

### Visual overhaul — tables & inventory
- Given I view the inventory table, when rows render, then alternating rows have a subtle `bg-surface` / `bg-surface-raised` stripe
- Given I hover over a table row, when the hover activates, then the row background transitions to `accent-glow` tint

### Visual overhaul — topology canvas
- Given the topology canvas renders, when I look at device nodes, then they are clean rounded rectangles (10px radius) with a coloured type icon on the left, device name as title (14px medium), and device type as subtitle (12px muted) — matching the workflow-builder node aesthetic
- Given a node is selected, when the selection renders, then the node gets a 2px accent-colour border — no glow halo
- Given edge labels render on the canvas, when I look at them, then labels sit on the line midpoint in a small pill-shaped badge (`bg-surface`, `border-radius: 9999px`, `1px solid {border}`) for readability over any background
- Given the current theme is Light, when Cytoscape.js renders, then node backgrounds are white with subtle borders, labels are dark text, and the canvas background is `bg-base`
- Given I switch themes while on `/topology`, when the theme updates, then Cytoscape.js styles re-apply without a full page reload

### Typography & spacing
- Given any page loads, when I inspect the font stack, then the body uses `Inter, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` (Inter loaded from Google Fonts CDN or bundled)
- Given page titles render, when I inspect them, then they use `font-size: 1.25rem; font-weight: 600`
- Given section headings render, when I inspect them, then they use `font-size: 0.875rem; font-weight: 600; text-transform: uppercase; letter-spacing: 0.5px; color: {text-secondary}`
- Given body text renders, when I inspect it, then it uses `font-size: 0.875rem; font-weight: 400`
- Given caption/subtitle text renders, when I inspect it, then it uses `font-size: 0.75rem; font-weight: 400; color: {text-secondary}`

### Transitions
- Given any interactive element (button, link, card, sidebar item), when I interact with it, then hover/focus/active states transition smoothly (150–250ms ease, no jarring snaps)
- Given I switch pages via the sidebar, when the content area updates, then there is a subtle fade-in (opacity 0→1, 150ms) on the new page content

### Design token architecture
- Given an engineer inspects `src/ui/design/tokens.py`, when they read the file, then all colour, shadow, radius, and transition values are defined as theme-aware dictionaries keyed by theme name — no hardcoded hex in any other `src/ui/` file
- Given an engineer wants to add a 4th theme, when they add a new entry to each token dictionary, then the theme engine picks it up with zero changes to components

## Non-Goals (explicitly out of scope)
- Per-user custom colour pickers / fully custom themes — three presets only in v1
- Animated page transitions beyond simple fade-in (no slide, no morph)
- Loading skeletons / shimmer placeholders for async data
- Glassmorphism / frosted glass effects — the design language is clean and solid, not translucent
- Custom iconography — continue using Material Icons
- `prefers-color-scheme` auto-detection — explicit toggle only (same as HT-015's decision)
- Mobile-specific visual adaptations beyond responsive sidebar (HT-026)

## Notes for Architect / Engineer

### Token architecture
Restructure `src/ui/design/tokens.py`:
```python
# Theme definitions — each theme is a dict of semantic tokens
THEMES = {
    "dark": { "bg_base": "#0f0f1a", "bg_surface": "#1a1a2e", ... },
    "light": { "bg_base": "#f8fafc", "bg_surface": "#ffffff", ... },
    "midnight": { "bg_base": "#050510", ... },
}
```
At runtime, inject theme values as CSS custom properties on `<body>` via `ui.add_head_html()` or `ui.run_javascript()`. All component styles then reference `var(--bg-base)`, `var(--accent)`, etc. Theme switching updates the CSS variables — no page reload needed.

### Cytoscape.js theme sync
After theme switch, call `cy.style().fromJson(newStyles).update()` to re-apply node/edge styles using the new token values. Wrap this in a JS function callable from Python via `ui.run_javascript('updateCyTheme(themeName)')`.

### Inter font
Add `<link>` to Google Fonts in `ui.add_head_html()` inside the app shell (HT-026). Fallback to system font stack.

### Migration path
- All existing `COLOR_*` constants in `tokens.py` remain as aliases pointing to the default ("dark") theme values for backward compatibility during the migration.
- After all components are converted to CSS variables, the flat constants can be removed in a follow-up cleanup.
