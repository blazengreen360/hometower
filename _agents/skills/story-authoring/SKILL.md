# story-authoring

Use this skill when product work needs to become an executable story.

## Read First

- `AGENTS.md`
- `.github/skills/hometower-product/SKILL.md`

## Product Science

- **Toyota 5 Whys**: push past the proposed solution until the actual user problem is clear
- **Jobs-to-be-Done**: define who is hiring Hometower to do what job
- **Kano Model**: label Basics, Performance gains, and Delighters
- **MoSCoW**: keep priority explicit
- **Minimal Viable Story**: split work until each story can ship independently

## Story Rules

- write explicit non-goals to prevent scope creep
- declare business invariants early so architecture has firm boundaries
- use rigid behavior-oriented acceptance criteria, preferably `Feature / Scenario / Given / When / Then`
- record unresolved architectural choices separately instead of burying them in prose
- for UI-heavy work, capture layout, state transitions, edge cases, and interaction triggers

## Output

Produce a story or backlog-ready draft with:
- title and priority
- job-to-be-done
- context
- acceptance criteria
- non-goals
- business invariants
- UX notes when relevant
